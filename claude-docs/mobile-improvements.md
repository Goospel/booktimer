# 📱 모바일 실기기 개선안 — 수집 노트

> **목적**: 사용자가 **모바일 실기기에서 BookTimer(미니앱·웹)를 실제로 쓰며** 발견한 개선안을,
> 그 자리에서 잊지 않도록 받아 적는 **수집함(inbox)**이다.
> 여기 적힌 것은 **아직 분석·설계 전의 날것**이다 — 원인·해법·우선순위는 나중에 컴퓨터에서 작업할 때 판단한다.
>
> **왜 파일인가**: 기록 전용 세션의 대화만 믿으면 세션이 사라질 때 같이 날아간다. 파일로 커밋해 두면 남는다. (2026-08-21 사용자 지시)
>
> **[plan.md](../plan.md)와의 관계** — plan.md의 `## 🩹 실사용에서 발견한 문제` 표는 **이미 손대서 원인·해결이 확정된 것**의 기록이다.
> 이 파일은 그 **앞단**이다: 여기 접수 → 작업 착수 시 분석 → 해결되면 plan.md 🩹 표로 승격하고 여기선 `✅ 완료`로 닫는다.
>
> 관련: [CLAUDE.md](../CLAUDE.md) · [plan.md](../plan.md) · [changelog](changelog.md) · [troubleshooting](troubleshooting.md)

## 적는 법

- 항목마다 **`M-#` 번호**를 붙인다(부여 후 재사용·재번호 금지 — 나중에 "M-7 해줘"로 지목하기 위함).
- 제목은 `### M-# · [화면] 한 줄 요약` — 목차만 훑어도 뭐가 있는지 보이게.
- **원문은 손대지 않는다.** 사용자가 적은 표현 그대로 두고, 해석은 `이해한 바`에 따로 적는다
  (해석이 틀렸을 때 원문이 남아 있어야 되돌릴 수 있다).
- 실기기에서 본 것이므로 **기기·화면(미니앱/웹)·상황**을 알면 같이 적는다 — 재현 가능성이 절반이다.

```markdown
### M-# · [화면] 한 줄 요약

- **상태**: 🆕 접수
- **적은 날**: YYYY-MM-DD
- **화면/영역**: (미니앱 홈 / 웹 내 책장 / …)
- **원문**:
  > 사용자가 적은 그대로

- **이해한 바**: (내가 해석한 문제·기대 동작 — 틀리면 사용자가 바로잡음)
- **메모**: (재현 조건·관련 코드·연관 항목 등. 없으면 생략)
```

## 항목

### M-1 · [미니앱 홈] 첫 방문 코치마크 진입점을 타이머 박스 자체로

- **상태**: ✅ 완료 (2026-08-24 — plan.md 🩹 표로 승격)
- **적은 날**: 2026-08-23
- **화면/영역**: 미니앱 홈 — 상단 첫 사용 안내 배너 / 타이머 히어로 카드
- **원문**:
  > 지금은 처음 들어오는 사람에게 보여주는 코치마크?가 상단에 뜨는데, 더 확실히 보이게 개선하자.
  > 타이머 박스 자체를이용하는거야. 처음들어오는 사람은 그 부분이 타이머게 아닌 코치마크 시작 버튼인 셈이지.

- **이해한 바**: 첫 방문 안내(코치마크 투어)의 **진입점을 상단 배너에서 타이머 박스(히어로 카드) 자체로 옮긴다.**
  처음 온 사람에게 그 자리는 타이머가 아니라 **「안내 시작」 버튼**으로 보이고, 누르면 투어가 시작된다.
  홈에서 가장 크고 시선이 먼저 닿는 요소를 안내의 문으로 써서 **발견율을 올리자**는 것 — 지금 상단 배너는 놓치기 쉽다.
- **메모**:
  - 관련 코드: `miniapp/src/coachmark.tsx`(`Coachmark`·`CoachmarkBubble`, `booktimer.coachmark.*` localStorage 키,
    `setCoachmarkWalking`) / `miniapp/src/screens/Home.tsx`(배너 자리는 헤더 바로 아래 — 894~900·1011줄 주석,
    배너 노드를 **만드는 쪽은 `MainTabs`**라 흐름은 거기서 본다).
  - ⚠️ **T-183 제약과 충돌하지 않는지 확인할 것** — 「진입 직후 화면을 덮는 것 금지」(시트·딤·모달·툴팁 전부, 심사가
    2회 반려한 자리). 이 안은 **화면 안 요소를 사용자가 눌러 시작**하는 형태라 원칙적으로 안전하지만,
    구현 시 *누르기 전엔 아무것도 덮지 않는다*를 지켜야 하고, 판정은 코드 판독이 아니라
    `localStorage.clear()` → 진입 → `position:fixed` · `z-index ≥ 99` 요소 0개 **실측**으로 한다.
  - ❓ 열린 질문(설계 때 정할 것): 투어를 **끝냈거나 거절한 뒤**엔 그 박스가 평범한 타이머로 돌아가는가?
    안내는 됐고 **바로 측정부터 하고 싶은 첫 방문자**의 경로는? (박스를 통째로 버튼화하면 첫 측정이 한 단계 멀어진다)

- **결과 (2026-08-24 구현)**: 히어로 카드의 **속만** 안내가 가져간다 — 껍데기(연필 테두리·독서등 표식)는 홈이
  그대로 들고 있어 자리가 안 흔들리고, 투어를 시작하거나 ✕로 닫으면 **그 자리에서 평소 타이머로 돌아온다**.
  - ❓ 열린 질문의 답 — **첫 측정은 멀어지지 않았다.** 이 앱에서 측정을 여닫는 자리는 **탭바 가운데 원**이고
    히어로 카드는 원래부터 버튼이 아니었다(목 모드 실측: 안내 카드가 떠 있는 상태에서 「측정 시작」이 그대로 눌렸다).
    카드 안 손잡이(ⓘ·「변경 ›」·「목표 정하기」)만 안내가 떠 있는 동안 물러난다.
  - 범위 조정 — **측정 중에는 안 뜬다**. 카드 자리를 가져가면서 생긴 새 제약이다(배너였을 땐 위아래로 나란히 서서
    둘 다 보였지만, 이제 안내가 뜨면 「측정 중 N분」이 통째로 가려진다).
  - T-183 실측(목 모드, `localStorage.clear()` → 진입): `position:fixed` · `z-index ≥ 99` 요소는 **탭바(z=100) 하나뿐** —
    딤·시트·모달 0개. 거절 후 재진입도 0개(그 경로가 실제 재발 자리였다). 콘솔 error·warn 0건.
