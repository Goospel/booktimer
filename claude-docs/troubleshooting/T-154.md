# T-154 · 클로드 내부 브라우저 패널이 닫혀 있으면 스크린샷·클릭만 타임아웃 난다 — 읽기 도구는 멀쩡해서 "확인했다"는 착각이 남는다

증상: 미니앱 목 모드 dev 서버를 띄우고 화면을 보여주려는데 `computer{action:"screenshot"}`이 5초 만에 `Screenshot timed out … the Browser pane is not displayed, so the page is not compositing frames`로 실패하고, 탭 클릭(`computer{left_click}`)은 30초 타임아웃으로 끝났다. 정작 서버는 정상이고(vite `ready` 로그, `read_page`가 전 화면을 정상 렌더로 반환) 콘솔 에러도 0건이라, 앱 버그나 서버 문제로 오인하기 쉽다. / 원인: 내부 브라우저 도구(`mcp__Claude_Browser__*`)가 붙은 패널은 **사용자 화면에 그 패널이 표시돼 있는 동안만** 프레임을 합성한다. 숨겨져 있으면 합성이 멈춰 **픽셀이 필요한 작업(스크린샷·좌표 클릭)만** 타임아웃하고, DOM만 만지는 `read_page`·`javascript_tool`·`read_console_messages`는 그대로 동작한다. **이 비대칭이 함정의 핵심이다** — 읽기 도구로 화면 내용을 전부 확인할 수 있으니 "UI 확인했다"고 보고까지 할 수 있는데, 정작 **사용자는 아무것도 못 본다**. 실패가 "안 보인다"가 아니라 "나만 보인다"로 나타나 자각되지 않는다. / 해결: 사용자의 실제 데스크톱 크롬(`mcp__claude-in-chrome__*`)으로 `http://localhost:5174`를 열면 확장이 붙어 있어 패널 없이도 스크린샷·조작이 되고, 무엇보다 사용자가 같은 화면을 직접 본다. / 재발방지: CLAUDE.md 「🖥️ 프론트 검증」 절에 **브라우저 확인 기본 = 데스크톱 크롬**으로 승격 기재(전 프로젝트 공통분은 글로벌 CLAUDE.md에도 신설 — goospel-claude-config #34). dev 서버 기동(`preview_start`)만 내부 도구가 유일 경로라 예외로 남긴다. 같이 실측한 함정 둘도 그 자리에 박았다 — ① `.claude/launch.json`은 gitignore 대상(머신 로컬)이라 **새 워크트리·새 PC엔 `miniapp-mock` 항목이 아예 없다**(없으면 다시 넣고 시작) ② **vite dev 서버는 `::1`(IPv6)에만 바인딩**이라 `127.0.0.1:5174`는 안 열리고 `localhost:5174`로만 열린다. 훅 하드 강제는 하지 않았다 — 내부 브라우저 도구를 통째로 차단하면 `preview_start`까지 막혀 dev 서버 자체를 못 띄우고, 크롬 확장이 꺼져 있을 때 대체 경로가 사라진다(승격 사다리대로 2회+ 재발하면 warn 룰부터). 1회차 신규 — "계측기는 통과했는데 정작 확인해야 할 것은 확인 못 함" 결이 T-150(비변별 배포 마커)·T-144(공허한 테스트)와 닿고, "preview로는 못 보는 것"이라는 점에서 T-053·T-054(헤드리스 로드순서) 군과도 스치지만, 이쪽은 원인이 코드도 테스트도 아닌 **도구 표면의 가시성 조건**이라 메커니즘이 별개다. 재발·승격 트래커에는 올리지 않고, 같은 메커니즘이 2회째가 되면 군을 만든다. 미니앱 UI를 사용자에게 보여주려던 중 발생
