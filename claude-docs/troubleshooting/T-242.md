# T-242 · 다른 워크트리로 `cd`해서 커밋하면 커밋 게이트 훅이 조용히 통과한다 — 훅은 세션 cwd만 본다

**1회차** / 증상: 2026-09-13 공부 타이머 병렬 작업(PR #1114)에서 서브에이전트가 `cd "C:/Users/kimsa/ClodeProjects/BookTimer-sg-push" && git commit -F .commit-msg-tmp`로 워크트리 B에서 커밋했는데, `require-tests-before-commit.ps1`이 `.java` 스테이징 커밋 **2개 연속**에서 `./gradlew test`를 돌리지 않았다. 차단도 경고도 없어 게이트를 통과한 커밋과 구별되지 않았다. 발견 단서: 테스트 결과 폴더에 돌연변이 실행 때의 3개 클래스 XML만 남아 있었다(전체 스위트가 돌았다면 수백 개가 있어야 한다). / 원인: 훅은 입력 JSON의 `cwd`(세션 주 폴더 — 33행 `$cwd = [string]$data.cwd`)에서 `git -C $cwd diff --cached --name-only`(51행 — #1119 UTF-8 stdin 수정 전엔 31·49행)를 본다 — **명령 문자열 안의 `cd` 대상은 모른다.** 세션 폴더엔 스테이징이 없으니 「`.java` 변경 0」으로 판정해 게이트를 건너뛴다. 「건너뜀」은 문서·설정 커밋의 정상 경로라 성공과 같은 얼굴이다. 같은 원리로 `$data.cwd`를 쓰는 다른 훅(`require-bundle-build.ps1` 번들 검사 · `require-changelog-no-dup.ps1` push 중복 행 검사 · `require-troubleshooting-toc.ps1` 목차 재생성 · `require-css-comment-safe.ps1` · `check-commit-message.ps1` · `block-main-push.ps1`)도 사각일 가능성이 높다(미실측). / 해결: 구현자가 커밋된 코드로 전체 스위트를 직접 돌려 실패 0을 확인했다(2,344·2,346건). 웹 워크트리는 코디네이터가 번들을 재빌드해 `git status` 무변경으로 번들=소스를 확인했다. / 재발방지: ① **병렬 워크트리에서 커밋할 땐 훅에 의존하지 말고 그 워크트리에서 테스트·번들 검사를 직접 돌린다**(서브에이전트 디스패치 프롬프트에 명시). ② 하드픽스 — 훅이 명령의 `cd`/`git -C` 대상 폴더를 추출해 그 폴더를 검사 — 는 별도 세션에서 진행 중. ③ 게이트가 「건너뛰었다」를 조용히 반환하지 말고 **왜 건너뛰었는지(어느 폴더를 봤는지)** 한 줄 남기면 이 클래스는 눈에 띈다. / **관련**: 같은 뿌리의 기존 항목은 없다 — T-105·T-115는 「세션 cwd」가 폴더 삭제를 막는 다른 현상, T-095·T-096·T-110은 워크트리 머지·정리 절차다. 글로벌 「통과는 증거가 아니다」(게이트 통과 = 검사 실행이 아니었다). 1회차라 재발·승격 트래커에는 올리지 않는다. / **승격(2026-09-13, 하드픽스)**: 재발방지 ②를 닫았다 — 공유 헬퍼 `.claude/hooks/lib/resolve-target-cwd.ps1`이 명령 속 `cd`·`Set-Location`·`git -C`를 따라가 워크트리 최상위를 돌려주고 훅 7개가 그 값을 쓴다. 「미실측」이던 나머지 6개도 테스트로 사각을 실측한 뒤 함께 닫았다(`test-hook-target-cwd.sh` 57건). 경로가 확장식(`cd "$WT"`)이라 알 수 없으면 게이트형 5개는 이 항목 번호를 단 메시지로 차단한다. ⚠️ **재분류**: 위 「같은 뿌리의 기존 항목은 없다」와 달리 **T-228(자기 스테이징 명령의 빈 인덱스)과 뿌리가 같다** — 둘 다 훅이 「PreToolUse 시점 + 세션 cwd」라는 자기 관점에서 상태를 읽는데 명령은 그 관점 밖에서 일해 게이트가 조용히 빠졌다. 그래서 트래커에 두 항목을 한 군(2회, 하드픽스)으로 올렸다. 재발방지 ③(어느 폴더를 봤는지 한 줄)은 하지 않았다 — 검사 대상을 바로잡으면 그 흔적이 필요한 자리가 확장식 경로뿐이고, 거기엔 차단 메시지가 선다.
