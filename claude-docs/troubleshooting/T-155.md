# T-155 · AWS CLI에 MSYS 경로(`file:///c/...`)를 주면 `Unable to load paramfile`로 실패한다 — Git Bash 변수에 담긴 `/c/...`가 그대로 새어 나간다

증상: 운영 DB를 SSM Send-Command로 조회하려고 `--parameters file://$PARAMS`(PARAMS = 스크래치패드 경로 `/c/Users/.../params.json`)를 넘겼더니 `Error parsing parameter '--parameters': Unable to load paramfile file:///c/Users/...`로 즉사한다. 파일은 분명 그 자리에 있고 같은 셸에서 `cat`도 된다 — 그래서 경로가 아니라 JSON 형식·권한을 먼저 의심하게 된다. / 원인: AWS CLI v2는 **Windows 네이티브 바이너리**라 MSYS(Git Bash) 가상 경로 `/c/...`·`/tmp/...`를 모른다 — Git Bash만 아는 마운트 표기다. `mktemp` 결과나 `$SCRATCH` 류 변수가 그 형태를 담고 있으면 그대로 터진다. T-136이 곁가지로 적어 둔 "경로는 `file://C:/...`"와 같은 뿌리지만, 그쪽은 cp949 인코딩 맥락이라 경로 함정이 묻혀 있었다. / 해결: **`cygpath -m`으로 Windows 형식(`C:/...`)으로 변환해** `--parameters "file://C:/..."`로 넘긴다 (`-m`은 슬래시를 유지해 `file://`에 그대로 붙는다). 같은 절차에서 함께 밟은 자매 함정 2종도 같이 적어 둔다 — **이 머신엔 jq가 없어** params.json은 파이썬 `json.dumps`로 만들고, SQL은 인라인 대신 **base64로 임베드**해 원격에서 디코드한다(따옴표 지옥 회피). / 재발방지: ① 절차 자체를 도구화 — `.claude/scripts/prod-db-query.sh`가 읽기 전용 가드·base64 임베드·`cygpath -m` 변환·SSM 폴링을 내장하고, `.claude/scripts/tests/test-prod-db-query.sh`가 dry-run 출력에 `file://C:/`가 들어 있는지를 단언한다(cygpath를 빼면 이 테스트가 죽는다 — 돌연변이 실측). ② 글로벌 hookify warn 룰 `warn-aws-msys-path` 신설 — `~/.claude/hookify/warn-aws-msys-path.md`, aws 명령에 `file:///c/` 꼴이 보이면 경고한다(자매 함정 jq 부재도 `warn-jq-not-installed`로 같이 걸림). 1회차 신규 — 재발·승격 트래커 미등록
