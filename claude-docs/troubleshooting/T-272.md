# T-272 · Git Bash `grep -c $'\r$'`는 줄끝 계측기가 아니다 — 직접은 CR을 떼고, `"$(…)"` 안에서는 CR이 사라져 모든 줄에 맞는다

**증상**: 설계 문서 두 개를 고치기 전 BOM·EOL 보존(글로벌 CLAUDE.md 인코딩 원칙 3)을 확인하려고 `grep -c $'\r$' "$f"`와 `wc -l`을 비교했다. 결과가 거꾸로 나왔다.
- LF 파일 `2026-10-17-booktimer-app-v1.md`(CR 0바이트)는 `CRLF줄=2054 전체줄=2054`로 나왔다.
- 작업 트리에서 CRLF인 `plan.md`(그 시점 CR 6097 · LF 6097 — core.autocrlf=true)는 `CRLF 0`으로 나왔다.
- 반영을 맡은 서브에이전트는 Python 바이트 판정으로 「원본은 LF」라고 맞게 보고했다. 반면 diff 검증 서브에이전트는 같은 `grep -c $'\r$'`로 「CRLF 2157 = 2157, 형식 OK」를 냈다. 결론(줄끝 보존)은 우연히 맞았지만 근거가 틀린 통과였다.

**원인**(대조 파일 실측 — 이 머신 Git Bash, GNU grep 3.0 · bash 5.2.37 msys. `eol-lf.txt` = `a\nb\nc\n`, `eol-crlf.txt` = `a\r\nb\r\nc\r\n`)

| 명령 | LF 파일 | CRLF 파일 |
|---|---|---|
| `grep -c $'\r$' f` (직접) | 0 | **0** |
| `printf … "$(grep -c $'\r$' "$f")"` (`"$(…)"` 안) | **3** | 3 |
| `"$(grep -U -c $'\r$' f)"` (`-U`를 붙여도 `$(…)` 안) | **3** | 3 |
| `CR=$(printf '\r')` 뒤 `grep -U -c "${CR}\$" f` | 0 | 3 |
| `tr -cd '\r' < f \| wc -c` | 0 | 3 |

- **직접**: Git Bash의 grep은 `-U`(binary) 없이 열면 CR을 떼고 맞춘다(줄 어디의 CR이든 — `grep -c "$CR"`도 0) → CRLF 파일에서도 `\r$`가 맞지 않는다.
- **`"$(…)"` 안**: 같은 `$'\r$'`가 모든 줄에 맞는다(LF 파일 포함). Bash 도구 탓이 아니다 — 스크립트 파일(`bash x.sh`)과 `bash -c`에서도 같다. 이 머신의 MSYS bash는 `$(…)` 안의 CR을 버린다. `$'\r'` · `$'\x0d'` · 소스에 박힌 CR 바이트가 모두 사라져 패턴이 `$`가 되고(`\t`는 남는다; `printf %s $'\r$' | od -c`를 `$(…)` 안에서 돌리면 `$` 하나만 나온다), 백틱과 변수(`CR=$(printf '\r')` 뒤 `"${CR}"`)는 CR을 지킨다. 그래서 `-U`를 붙여도 `"$(grep -U -c $'\r$' f)"`는 LF 파일에서 3이다. 같은 줄에 이 꼴을 두 번 쓰면 `unexpected EOF while looking for matching ')'`로 파싱되지 않는 것도 스크립트 파일에서 그대로 재현된다. MSYS bash가 왜 그러는지 소스로는 확인하지 않았다(관측된 동작만 적는다).
- 두 경우 모두 양성 대조군(CR이 있는 걸 아는 파일)을 같이 돌리지 않으면 숫자가 그럴듯해 보인다. 「통과는 증거가 아니다」의 계측기 고장이다.

**해결**: CR은 바이트로 센다.
- 셸: `tr -cd '\r' < f | wc -c` / `tr -cd '\n' < f | wc -c`. CR 수가 LF 수와 같으면 CRLF, 0이면 LF다.
- 또는 `node -e` / Python으로 바이트 13·10을 센다. git 쪽은 `git ls-files --eol <파일>`의 `w/` 열(추적 파일만 — 미추적·무시 파일은 빈 출력으로 끝나니 `-o`를 붙인다).
- grep을 꼭 써야 하면 `-U`를 붙이고, CR은 `$'\r'` 대신 `CR=$(printf '\r')`로 만든 변수를 넘긴다(`$(…)` 안에 넣을 때도 변수로).

**재발방지**
- 줄끝 판정 명령에는 양성 대조(CRLF로 아는 파일 하나)를 같이 돌린다. 줄끝 확인을 서브에이전트에 맡길 때는 브리프에 「`grep -c $'\r$'` 금지, `tr -cd '\r' | wc -c`」를 적는다.
- 이번이 2회차다 — 2026-10-07 `~/.claude/docs/2026-10-07-claudeprojects-rename-design.md`(39줄)에 「Git Bash의 `grep -c $'\r$'`는 CR이 없는 파일도 센다」는 같은 실측이 적혀 있었다(설계 문서라 T 검색에 걸리지 않았다). 그래서 다음 회차를 기다리지 않고 하드 가드를 제안한다: hookify 경고 룰 — Bash 명령에 `grep`과 CR 패턴(`\r` · `\x0d`)이 있으면서 ① `-U`가 없거나 ② `$'…\r…'`가 `$(` 안에 있으면 경고(②는 `-U`가 있어도 LF 파일을 3으로 센다). 글로벌 규칙 추가라 사용자 승인이 나는 대로 `/hookify`로 넣는다.
