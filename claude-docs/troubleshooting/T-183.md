# T-183 · 심사는 「진입 직후 들이대는 것」을 막는다 — 자동 노출을 없애도 게이트가 열린 인라인 안내가 같은 사유를 재발시킨다

증상: 토스 심사 반려 — 「미니앱 접속 직후 바텀시트가 바로 노출돼요. 진입 시 즉시 나타나지 않도록 수정해 주세요.」 우리 코드에 「바텀시트」는 측정 종료 후 태깅 시트뿐이라 처음엔 무엇을 봤는지 몰랐다. / 원인: **코치마크 첫 걸음이었다.** 목 모드에서 `localStorage.clear()` 후 첫 진입을 재현해 확정했다 — 우리가 만든 것은 툴팁이지만 렌더 결과가 **전체 딤 + 하단 좌우 24px 와이드 패널**(폭 342px = 화면의 88% · 하단 고정 · 배경 잠김)이라 시트와 구별할 근거가 없었다. 2026-08-12 「서비스 설명 없이 즉시 토스 로그인 유도」 반려와 **같은 군**이다: 심사가 막는 것은 「시트」라는 모양이 아니라 **진입 직후 동의 없이 화면을 덮는 행위**다. / 해결: 안내 구현은 그대로 두고 **시작 트리거만 자동 → 수동**으로 뒤집었다(홈 헤더 아래 1회성 배너 + ✕). 표시 기준은 **길 안내 미완**뿐이다 — 「전 걸음 완료」로 하면 책 0권이라 여백 문이 없는 신규 사용자에게 배너가 평생 뜬다. ⚠️ **여기서 끝낸 줄 알았는데 실 브라우저가 구멍 2건을 더 잡았다**: ① ✕를 눌러도 배너가 남았다 — 배너만 보고 있을 때 커서는 이미 `-1`이라 `setFlowIndex(-1)`이 같은 값이고 **React가 리렌더를 건너뛴다**(닫힘을 별도 상태로) ② **반려 사유 재발** — ✕로 거절하면 길 안내 키 3개가 남아 인라인 안내의 `after` 게이트가 **열리고**, 다음 진입 때 홈에서 여백 안내 딤이 즉시 깔렸다. 인라인 안내에 「걷는 중」 잠금(`coachmarkWalking` — 기기에 남기지 않는 모듈 지역 상태)을 달아 흐름이 살아 있을 때만 뜨게 했다. / 재발방지: ⓐ **진입 직후 자동으로 화면을 덮는 것을 만들지 않는다**(시트·딤·모달·툴팁 전부 — CLAUDE.md 미니앱 절로 승격, 2회차). ⓑ 「자동 노출을 껐다」의 판정은 **첫 진입을 실제로 재현**해서 한다: `localStorage.clear()` → 진입 → **fixed·z-index≥99 요소 0개**를 세고, **거절·완주·재방문까지** 밟는다(거절 경로가 이번의 재발 지점이었다). ⓒ 자동 노출을 없애는 변경은 **그 기능의 옛 테스트를 무력화한다** — 부재 단언이 영영 참이 되므로(T-149·T-180·T-181 계열) 계측을 컴포넌트 직접 렌더로 옮긴다. 이번엔 옛 테스트 7건이 깨져 그 사실을 알려 줬다. **관련**: T-182(같은 하니스의 사각) · T-053 군(검증 환경이 관대) · plan 「심사 반려 대응 — 진입 인트로 + 플로팅 탭바」(1회차)
