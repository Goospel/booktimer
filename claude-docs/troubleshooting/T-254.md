# T-254 · 돌연변이 주입 스크립트가 gradle을 한 번도 안 돌리고 「전부 사살」을 보고했다 — 한 세션에서 두 사람이 같은 함정에 빠졌다

**2회차**(같은 세션 내 독립 재발: 구현 서브에이전트 1회 + 리뷰어 1회) / 증상: `GeneralBookNewsFeed`의 규칙 4종을 지우는 주입기를 돌리자 네 줄 모두 「사살」이 찍혔다. 그런데 `build/test-results/test/*.xml`의 `timestamp`가 **주입 전과 똑같았다** — 테스트가 아예 안 돌았고, 「사살」은 실패한 **명령**(gradle 미실행)을 실패한 **테스트**로 읽은 것이었다. 즉 규칙을 지워도 초록인지 붉은지 이 실측은 **아무것도 말하지 못했다**. / 원인: Windows에서 node `execSync('./gradlew test …')`가 기본 셸(cmd)로 떠 `./gradlew`를 못 찾고 즉시 던진다. 주입기의 try/catch가 그 예외를 **「테스트 실패 = 사살」**로 분류했다 — 예외의 출처가 **테스트냐 실행 자체냐**를 안 갈랐다. 「통과는 증거가 아니다」의 정확한 거울상이다: 여기선 **실패 쪽**이 증거로 오인됐고, 그래서 결론이 언제나 「사살」로 고장 난다(모든 돌연변이가 100% 잡히는 것처럼 보인다 — 너무 좋은 결과가 신호였다). / 해결: 주입기에 **게이트 3개**를 박았다 — ① **주입 단언**: 치환 대상이 소스에 정확히 1건 매치인지 세고(0건·2건이면 크래시), 쓴 뒤 읽어 바이트가 실제로 달라졌는지 확인 ② **실행 단언**: 실행 전후 JUnit XML의 `timestamp="…"`를 비교해 **같으면 크래시**(「테스트가 안 돌았다」) ③ **복원**: 원본 **바이트**를 그대로 되쓰고 끝에 `git diff --numstat`으로 변경 0을 확인. 셸은 `execSync(..., { shell: 'C:/Program Files/Git/bin/bash.exe' })`로 명시한다. 사살 목록은 exit code가 아니라 XML의 `<testcase …><failure` 이름에서 뽑는다. / 재발방지: **돌연변이 실측의 결론은 「명령이 실패했다」가 아니라 「테스트 결과 파일이 새로 쓰였고 거기에 실패가 있다」로 낸다.** 주입기를 새로 쓸 때 위 3게이트가 없으면 그 실측은 보고하지 않는다 — 특히 **전부 사살**이 나오면 게이트부터 의심한다(정상 실측은 대개 한둘이 살아남아 테스트를 보강하게 만든다). ⚠️ 이 함정은 **사람이 아니라 하네스에 있다** — 같은 세션에서 구현자와 리뷰어가 서로 모른 채 똑같이 빠졌고, 리뷰어 쪽은 ②가 이미 박힌 주입기를 써서 **크래시로 즉시 드러났다**(게이트가 값을 한 것이 실측됐다). / **관련**: 「통과는 증거가 아니다」(글로벌 CLAUDE.md — 양성 대조군 없는 검사는 음성 판정만 가능) · T-253(계측기가 사라져도 초록인 자리)
