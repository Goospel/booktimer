# T-264 · TaskStop으로 dev:mock을 멈춰도 vite가 포트를 쥐고 남는다

## 증상

- 백그라운드로 띄운 `npm --prefix miniapp run dev:mock -- --port 5303 --strictPort`를 `TaskStop`으로 멈추면 「Successfully stopped」가 나온다.
- 그런데 `Get-NetTCPConnection -LocalPort 5303 -State Listen`을 보면 리스너가 그대로 있다. 주인은 `…\miniapp\node_modules\.bin\..\vite\bin\vite.js --mode mock --port 5303 --strictPort`를 명령줄로 가진 `node`다.
- 2026-10-12~13 에디토리얼 재테마 작업에서 서브에이전트 다섯 번, 메인 세션 두 번, 같은 일이 났다(PID 15240 · 13800 · 11332 · 22112 · 17824 · 6556 · 18252 · 1312 · 25012 · 30464 등).

## 원인(추정)

- Windows에서 `npm`은 셸을 거쳐 `node vite.js`를 손자 프로세스로 띄운다. TaskStop은 바깥 셸·npm을 끝내지만 손자 node는 고아가 되어 남는 것으로 보인다.
- 실측은 「TaskStop 성공 뒤에도 이 폴더 vite.js 명령줄의 node가 그 포트를 듣는다」까지다. 프로세스 트리 구조 자체는 확인하지 않았다.

## 해결

명령줄로 내 것인지 확인한 뒤 그 PID만 끈다. 포트 번호와 폴더 이름은 띄운 것에 맞춘다.

```powershell
Get-NetTCPConnection -LocalPort 5303 -State Listen -EA SilentlyContinue | ForEach-Object {
  $p = Get-CimInstance Win32_Process -Filter "ProcessId=$($_.OwningProcess)"
  if ($p.CommandLine -like '*BookTimer-pr4-rest*vite*') { Stop-Process -Id $p.ProcessId -Force; "종료 $($p.ProcessId)" }
  else { "남의 것: $($p.CommandLine)" }
}
```

## 재발 방지

- 띄운 쪽이 끝낼 때 위 절차까지 밟는다. TaskStop의 「성공」은 포트가 비었다는 증거가 아니다.
- `Get-Process node | Stop-Process`처럼 머신 전체의 node를 끄지 않는다. 다른 세션의 dev 서버와 빌드를 함께 죽인다(T-235 곁다리와 같은 이유).
- 판정 전에는 서버가 이 폴더의 것인지 `fetch('/src/<방금 고친 파일>?raw')`에 이번 변경의 식별자가 있는지로 확인한다(browser-verify 함정 ③).

- **2회차** 2026-10-13 — 이 파일을 쓴 뒤 같은 날 일곱 번 더 났다(스크린샷 촬영·리뷰·반영 에이전트 PID 24400 · 25484 · 11968 · 12264, 달 라벨 설계·구현 에이전트 4884 · 24224, 메인 세션 2716). 모두 「TaskStop 성공 → 5300·5303 리스너가 이 폴더 vite」의 같은 꼴이었고, 위 「해결」 절차로 매번 정리했다. 문서 처방은 정리는 하게 해도 재발은 못 줄인다 — 자동 장치 후보(/hookify 제안, 2026-10-14 수면 보고서): TaskStop 직후 그 작업의 포트를 듣는 같은 폴더 vite를 알려 주는 훅, 또는 dev:mock을 npm을 거치지 않고 vite.js로 직접 띄워 TaskStop이 그 프로세스를 끄게 하기
