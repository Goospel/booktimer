# T-204 · Jackson 3은 `FAIL_ON_NULL_FOR_PRIMITIVES`가 기본 켜짐 — 요청 record에 선택적 `boolean`을 더하면 그 필드를 안 보내던 옛 클라가 통째로 500

증상: `CreateStoryRequest`에 `boolean shared`를 추가하자 **손도 안 댄 기존** 「글 남기기」 테스트 7건이 동시에 붉어졌다. 새 필드와 무관한 경로가 무너지니 원인이 새 필드로 안 보이고, 신규 기능 쪽을 먼저 파게 된다. 메시지는 `Cannot map null into type boolean`. / 원인: Jackson 3은 `FAIL_ON_NULL_FOR_PRIMITIVES`를 **기본 활성**으로 바꿨다(Jackson 2는 비활성이라 필드 부재가 조용히 `false`로 채워졌다). 즉 **「프리미티브면 필드 부재 = false가 공짜로 성립」이라는 통념이 Jackson 3에서 뒤집힌다** — 이 레포의 설계 문서에도 그 문장이 그대로 적혀 있었고, 틀렸다는 것은 테스트가 붉어져서야 드러났다. / 해결: 래퍼 `Boolean` 필드 + `Boolean.TRUE.equals(shared)` 접근자. 옛 클라(필드 아예 없음)와 `shared:null` 명시 요청 **양쪽**을 회귀 테스트로 못 박았다 — 둘은 다른 경로라 하나만 잡으면 나머지가 샌다. / 재발방지: ① **요청 DTO에 선택적 boolean을 더할 땐 래퍼 `Boolean`으로.** 프리미티브를 쓰는 것은 Jackson 3에서 「이 필드는 필수」라는 선언이 된다. ② 옛 클라 호환은 **「그 필드가 아예 없는 JSON 바디」 테스트**로 못 박는다. ③ 이 레포의 기존 선택 필드가 전부 객체 타입(`String`·중첩 record)이라 여태 이 함정을 안 만났다 — boolean이 첫 프리미티브 선택 필드였다. 그래서 **「기존 테스트가 무더기로 깨지면 새로 더한 필드의 타입부터 본다」**가 이 클래스의 진단 첫 수다. 1회차 신규
