# T-228 · 커밋 게이트 두 개가 조용히 스킵된다 — `git add -A && git commit -F ...`처럼 커밋 명령이 스스로 스테이징하면 PreToolUse 시점 인덱스가 아직 비어 있어 게이트가 그냥 통과한다

**1회차** / 증상: PR #1035에서 섬 번들 **7개가 stale인 채** 커밋됐는데 `require-bundle-build.ps1`이 `[BLOCKED] Bundle is stale`을 띄우지 않았다. 우회 토큰(`SKIP_BUNDLE_CHECK`·`SKIP_TESTS`)은 쓰이지 않았음이 트랜스크립트로 확인됐다. 양방향 확인: 파일을 먼저 스테이징하면 같은 상태에서 차단이 재현되고, `git add`를 별도 명령으로 끊으면 훅이 정상 동작한다. / 원인: 두 훅 다 「이 커밋이 무엇을 건드리나」를 **인덱스만** 보고 판단한다(`git diff --cached --name-only` → 0건이면 `exit 0`). 그런데 PreToolUse는 명령이 **실행되기 전**에 도니까, 스테이징이 그 명령 안에 들어 있으면 훅이 볼 때 인덱스는 아직 비어 있다. ⚠️ **테스트 게이트도 똑같은 구멍이었고, 번들보다 그쪽이 훨씬 위험하다** — `.java`를 고치고 `git add`를 커밋 명령에 묶으면 `./gradlew test`가 **아예 안 돌고** 커밋된다. 즉 「게이트 통과」가 「게이트가 돌았다」를 뜻하지 않는 상태였다. 덤으로 두 번째 무성 통과 경로도 드러났다: `$ErrorActionPreference=Stop`에서 git의 stderr 경고(`LF will be replaced by CRLF`)가 NativeCommandError로 승격돼 목록 수집이 통째로 예외가 되고, `catch`가 빈 목록을 만들어 역시 조용히 통과한다. / 해결: 두 훅에 `$selfStages` 판별을 넣었다(`git add`·`git stage`·`git commit -a/-am/--all`). 해당하면 인덱스에 더해 **작업 트리**까지 합쳐 게이트한다 — `git diff --name-only`(수정된 추적 파일) + `git ls-files --others --exclude-standard`(새 미추적 파일). 수집 구간은 `Continue`로 감싸 stderr 경고에 죽지 않게 했다. **fail-safe 방향**이다: `git add <일부 경로>`처럼 작업 트리가 실제 스테이징보다 넓으면 게이트가 **불필요하게 도는** 쪽으로 기운다(안 도는 쪽이 아니라). 스테이징이 이미 차 있는 정상 경로는 그대로다. / 재발방지: `.claude/hooks/tests/test-commit-gate-selfstaging.sh` **10건** — 사각 4건 + 양성 대조군 6건(정상 스테이징 경로 불변 · 문서만 바꾼 자기 스테이징 커밋은 여전히 통과 · `SKIP_*` 우회 유지). 대조군이 없으면 「전부 차단」하는 구현도 초록이라 필수다. 원칙: **훅을 짤 때 「무엇을 보고 판단하는가」가 훅이 도는 시점에 이미 존재하는지 확인한다** — PreToolUse는 명령 실행 **전**이라 그 명령이 만들 상태를 미리 볼 수 없다. / **관련**: T-153(검사가 통과 쪽으로 고장 나는 같은 계열
