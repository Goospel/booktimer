# T-192 · 전면 종이 결을 `position: fixed`로 깔면 스크롤할 때 결만 제자리에 남는다 — 결이 종이가 아니라 화면에 낀 유리가 된다

증상: 형님이 실기기에서 「배경이랑 요소들은 움직이는데 필터 무늬는 움직이지 않아서 어색하다」고 반려했다. 정지 화면만 보면 완벽해 보이고, 스크롤하는 순간에만 드러난다. / 원인: 종이 결 레이어 `body::before`가 `position: fixed`였다 — fixed는 **뷰포트**에 고정되므로 문서가 스크롤돼도 레이어는 그 자리다. 처음 fixed를 고른 이유는 성능이었다(값이 변하지 않는 fixed 레이어는 GPU 텍스처로 한 번 캐시된다). 그 판단이 **재질감의 의미**를 무시했다 — 결은 화면의 성질이 아니라 **종이의 성질**이라 종이와 함께 움직여야 한다. / 해결: `position: absolute` + 컨테이닝 블록이 될 `body { position: relative }`. ⚠️ 이 둘은 **한 쌍**이다 — 기준이 없으면 절대배치의 컨테이닝 블록이 **초기 컨테이닝 블록(뷰포트 크기)**이 돼, 결이 첫 화면 높이까지만 깔리고 그 아래는 민 종이로 남는다(조용한 실패다 — 스크롤해야 보인다). 미니앱은 `body { min-height: 100dvh }`도 함께 넣었다: 내용이 짧은 화면에서 body가 본문 높이까지만 자라 아래쪽에 결이 없어진다. 그리고 **z-index를 9999 → 90으로 낮췄다** — 안 낮추면 같은 어색함이 **뒤집혀 재발**한다: 결이 고정 요소(미니앱 탭바 100·시트 200/201, 웹 모달 100·150·200) 위를 덮은 채 문서가 스크롤하면 이번엔 무늬가 **탭바 위를 미끄러진다**. 본문 최대 z-index가 웹 61·미니앱 0이라 90이 「본문 위 · 떠 있는 것 아래」를 동시에 만족하는 밴드다. / 재발방지: ① 미니앱 테스트가 `position: absolute` 존재 + `fixed` 부재 + `body{position:relative}` + `z-index < 100`을 못 박는다(`ui.test.tsx` 「종이 결」). ② **전면에 깔리는 시각 요소(배경·오버레이·고정 레이어)를 만들거나 고쳤으면 반드시 스크롤해 보고 판정한다** — 이 결함은 동작 중에만 존재해 정지 스크린샷·computed style 조회로는 원리상 안 보인다(「검증 환경이 관대」 트랩군 8회차, 축은 콘텐츠도 엔진도 아닌 **동작**). ③ 노이즈처럼 눈으로 대조가 불가능한 무늬는 **임시로 굵은 줄무늬를 주입**해 스크롤 전후를 눈으로 보고, 정량 확인은 **같은 컨테이닝 블록의 프로브**(`position:absolute; inset:0` div)를 심어 `getBoundingClientRect().top`이 스크롤량과 **정확히 같은 양** 변하는지로 한다 — 의사요소는 JS로 기하를 못 재지만 배치가 같으면 기하도 같다.
