# T-170 · Flyway 버전 번호가 겹치면 그 스크립트만 실패하는 게 아니라 스키마 초기화가 통째로 거부된다 — 머지 전엔 어느 쪽에서도 안 보인다

증상: 리베이스로 base를 당긴 직후 `FlywayMigrationTest` **18건이 전멸**. 실패 메시지는 전부 `Failed to load ApplicationContext` + `ApplicationContext failure threshold (1) exceeded`라 **우리 변경과 무관해 보인다**(개별 단언이 아니라 컨텍스트 로딩 단계에서 죽는다). 리베이스 전에는 전량 그린이었다. / 원인: 병렬로 진행된 다른 브랜치가 먼저 머지되며 같은 `V68` 번호를 선점했다. Flyway는 중복 버전을 만나면 해당 스크립트를 건너뛰는 게 아니라 `FlywayException: Found more than one migration with version 68`로 **초기화 자체를 거부**한다 → 그 DataSource를 쓰는 클래스가 통째로 죽는다. **각자 워크트리에선 자기 V68이 유일**해서 작업 중엔 어느 쪽도 이걸 볼 수 없다. / 해결: 우리 것을 `V69`로 물리고(내용 무변경) 컬럼을 언급하던 주석·문서의 버전 표기도 따라 옮긴다. / 재발방지: ① 마이그레이션 파일을 만들기 전 **`git fetch origin` 후 원격 기준**으로 최신 번호를 잡는다 — 로컬 기준 「마지막 +1」은 병렬 작업에서 반드시 어긋난다. ② **리베이스·base 갱신 직후에는 전체 스위트를 한 번 돌린다** — 이 부류는 코드 리뷰로도 안 잡히고 base를 당긴 뒤에야 드러난다. ③ 한 클래스가 «전건» 실패하면 개별 단언 메시지가 아니라 **`Caused by` 체인 끝**을 먼저 읽는다(여기선 3단 아래 Flyway 예외가 진짜 원인이었다).
