# T-194 · 발행한 아티팩트는 sandboxed iframe 안이라 스크롤·JS 주입이 막힌다 — 시안 HTML을 「훑어보며 고치는」 검증은 로컬 정적 서버로 한다

증상: 검색 결과 시안 4장을 담은 HTML을 Artifact로 발행하고 크롬으로 열어 아래쪽 시안(B·C안)을 확인하려 했는데 **화면이 한 픽셀도 안 움직였다**. `computer` 스크롤도, 페이지를 클릭한 뒤 `Page_Down`도 무시됐고, `ctrl+minus` 줌아웃은 도구가 거부했다. 스크린샷은 매번 첫 화면만 정상으로 찍혀서 「페이지가 덜 로드됐나」로 오인했다. / 원인: 아티팩트 본문은 **`srcdoc` sandboxed iframe** 안에서 렌더된다. 휠·키 입력은 상위 문서가 받고 iframe 내부 스크롤로 전달되지 않으며, `iframe.contentDocument`가 `null`이라 JS로 스크롤을 주입할 수도 없다(`Cannot read properties of null`). 즉 **읽기(스크린샷)는 멀쩡한데 조작만 죽는** 상태다. / 해결: 발행 **전** 검증은 로컬에서 한다 — 스크래치패드에 20줄짜리 node http 서버를 띄우고(포트 8899) 크롬으로 `localhost:8899/<파일>`을 연다. iframe이 없으니 `window.scrollTo`도 `computer` 스크롤도 정상이고, `getComputedStyle`로 색·레이아웃을 수치로 뽑을 수 있다(이번에도 그렇게 접힌 모서리 그라데이션과 칩 색을 확인했다). 확인이 끝나면 포트를 반납한다. / 재발방지: ① **아티팩트는 「완성본을 건네는 자리」이지 「고치며 훑는 자리」가 아니다** — 반복 확인이 필요한 단계에선 로컬로 열고, 발행은 결과 전달용으로 쓴다. ② 조작만 막히고 읽기는 되는 증상은 **T-184(탭이 상해 CDP 경로 전체가 30초 타임아웃)와 감별**한다: T-184는 스크린샷까지 죽고 새 탭을 열면 즉시 풀리지만, 이건 스크린샷이 곧바로 정상으로 돌아오고 스크롤만 조용히 무시된다 — 새 탭으로도 안 풀리면 iframe 격리 쪽이다.
