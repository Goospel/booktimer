# T-239 · 바쁘면 즉시 반환하는 함수를 `await` 하면 조용한 no-op이 된다 — 부르는 쪽은 「다 끝났다」로 읽고, 증상은 데이터 파괴로만 드러난다

**1회차** / 증상: 웹 필기 자동저장(PR-2 #1085)에서 `flush()`가 `if (inflight) return;`으로 즉시 반환하는데, `openNote`/`newNote`가 `await flush()`의 반환을 「플러시 완료」로 믿고 `draft`를 갈아끼웠다. 결과 둘 — ① 저장 왕복 중 「＋ 새 필기」를 누르면 빈 초안에 **앞 장의 `id`가 박혀** 이후 입력이 `POST /notes/5`로 나가 앞 장을 덮어썼다(실측: 기대 `POST /notes` 생성) ② 왕복 중에 친 글자가 전환 때 사라졌다(실측: 나간 본문 `["A1","A2"]`, `A2A3` 유실). **자동저장이라 사용자가 알아챌 계기가 없고 화면엔 「저장됨 · 14:32」가 떴다.** 휴지통도 버전도 없어 복구 수단이 없다. / 원인: `await`는 「그 함수가 할 일을 마쳤다」가 아니라 **「그 함수가 반환했다」만** 보장한다. 조기 반환을 둔 함수는 바쁠 때 **아무 일도 안 하고 성공과 똑같은 모양으로** 반환하고, 호출부에 그 차이를 알릴 값이 없으면 구분이 원리상 불가능하다. 여기에 「응답이 오면 무조건 `draft.id`를 되쓴다」가 겹쳐 **늦게 온 응답이 새로 연 장을 오염**시켰다. / 해결: ① 왕복 프로미스를 보관해 `flush()`가 **그 왕복을 기다린 뒤 한 번 더** 저장 ② 초안에 세대 번호(`seq`)를 달아 응답 처리 직전에 「지금 열린 장의 것인가」를 대조(아니면 `id`·`revision`·상태를 전부 손대지 않는다) ③ 초안이 자기 `bookId`를 들고 다니게 해 전송 시점의 `bookId.value`를 읽지 않게 했다. / 재발방지: ① **조기 반환을 둔 async 함수는 「했다/안 했다」를 반환값으로 알린다**(boolean·상태). 아무것도 안 알리면 호출부는 성공으로 읽는다. ② **「바쁘면 건너뛴다」는 폴링·로깅엔 맞지만 사용자 데이터를 옮기는 경로에선 유실이다** — 그 자리에선 건너뛰지 말고 기다렸다가 다시 한다. ③ 훅·정적 분석 불가(조기 반환 자체는 정상 패턴이고, 위험 여부는 그 함수가 무엇을 옮기는가에 달렸다). 대신 **자동저장·디바운스·플러시 패턴을 새로 만들면 「전환·언마운트 시점에 왕복이 떠 있는」 경우를 테스트로 먼저 박는다** — 이번 4건이 전부 그 형태였고, 기존 「전환 플러시」 테스트는 **왕복이 없는 상태만** 재고 있어 이 구멍을 통째로 놓쳤다(계측기가 있었는데 겨눈 자리가 달랐다). / **관련**: 글로벌 「통과는 증거가 아니다 — 검사가 무엇을 배제하는지 먼저 적는다」(기존 테스트는 통과했지만 「왕복 중 전환」을 배제하지 못했다) · T-205(공허한 테스트 군 — 통과가 증거가 아닌 상태)
