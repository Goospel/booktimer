# T-159 · 웹뷰에서 `overflow-y: hidden`은 그 트랙의 가로 터치 스크롤까지 죽인다 — 세로를 막으려던 벨트가 캐러셀을 통째로 못 쓰게 만들었다. 겸사겸사 `scrollTo({behavior})`도 무시된다

증상: 심사 통과 후 배포한 홈 표지 캐러셀이 실기기에서 **좌우로 밀리지 않고**(옆 표지를 직접 탭해야만 골라짐) **탭해도 그 표지가 가운데로 오지 않았다**. 데스크톱 크롬 목 모드에서는 트랙이 정상 스크롤 컨테이너였고(`scrollWidth 402 > clientWidth 302`, `scrollLeft` 대입 → scroll 이벤트 → 선택 전환까지 정상) 콘솔 에러도 0이라 코드에서 원인이 안 보인다. / 원인: 셋이 겹쳐 있었다. ① **직전 핫픽스(#742)가 세로 들썩임 벨트로 넣은 `overflowY: 'hidden'`** — 웹뷰가 이 값을 만나면 해당 요소의 터치 스크롤을 축과 무관하게 통째로 죽인다. 회귀 시점이 그 커밋과 정확히 일치했다. ② **`scrollTo({left, behavior:'smooth'})`의 옵션 객체를 통째로 무시하는 웹뷰가 있다** — 미지원이면 에러 없이 아무 일도 안 일어나므로 "선택은 되는데 위치만 안 변함"으로 나타난다. ③ 스크롤 **도중** `onScroll`이 선택 state를 갱신하면 그 리렌더가 `scroll-snap-type: x mandatory`의 재스냅을 불러 손가락에서 스크롤을 빼앗는다. / 해결: ① `overflowY: 'hidden'` → **`touchAction: 'pan-x'`**(세로 제스처는 그대로 못 먹고 가로만 산다). 벨트를 빼도 들썩임이 재발하지 않는 근거는 그 핫픽스가 함께 만든 `TRACK_V_PAD`다 — 세로로 넘칠 여지가 이미 0(실측 `scrollHeight - clientHeight === 0`)이라 `overflow-y`가 auto로 계산돼도 스크롤할 게 없다. ② 애니메이션 주체를 JS → CSS로: 트랙에 `scroll-behavior: smooth` + 호출은 어디서나 먹는 `scrollLeft` 대입. 첫 진입만 `scroll-behavior`를 잠시 `auto`로 꺼 즉시 자리를 잡는데, **되돌릴 때 빈 문자열을 넣으면 React가 심은 인라인 `smooth`까지 지워지므로** 상수로 명시 복구한다. ③ 스크롤 멎은 뒤 한 번만 고르도록 120ms 디바운스(타이머는 언마운트 시 정리). / 재발방지: ① **스크롤 컨테이너에서 한 축을 막을 땐 `overflow-*: hidden`이 아니라 `touch-action`을 쓴다** — `overflow`는 "그 축을 못 넘게" 하려다 웹뷰에서 터치 입력 자체를 잃는다. 세로 넘침은 애초에 레이아웃(패딩)으로 0을 만들고, 제스처는 `touch-action`이 맡는 역할 분담. ② **웹뷰를 타는 코드에서 `scrollTo`의 options 형태에 의존하지 않는다** — CSS `scroll-behavior` + 위치 대입이 호환 범위가 넓다. ③ CSS 스냅 컨테이너에서 **스크롤 도중 리렌더를 만들지 않는다**(선택 갱신은 손을 뗀 뒤). ④ 교훈: **방어로 넣은 한 줄이 더 큰 기능을 부술 수 있다** — 벨트를 추가할 땐 그 벨트가 없어도 되게 만든 근본 수정(여기선 패딩)이 이미 충분한지 먼저 보고, 굳이 겹쳐 넣지 않는다. ⚠️ 브라우저로는 원인 확정이 불가능했다 — 자동화 크롬 탭이 백그라운드(`visibilityState: hidden`)면 **스크롤 이벤트가 발화하지 않고 smooth 애니메이션도 재생되지 않아**(window 전체 smooth도 `dy=0`) 증상 재현·수정 검증이 모두 막힌다(T-154의 사촌 — 저쪽은 패널 미표시로 픽셀 작업만, 이쪽은 탭 비가시로 프레임 의존 동작 전부). 확인 가능했던 것은 스타일 적용·목표 위치 계산까지고, 실제 스와이프와 디바운스 갱신은 **실기기가 게이트**다. 1회차 신규 — 「실기기에서만 드러나는 미니앱 시각·입력 결함」이라는 결이 T-152·T-154·T-156·T-157과 닿지만 메커니즘(웹뷰 overflow-터치 상호작용)이 별개라 재발·승격 트래커에는 올리지 않는다. 캐러셀 배포 후 실사용 중 발견
