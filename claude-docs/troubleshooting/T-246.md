# T-246 · 워크트리의 `frontend/node_modules`가 dependabot 전 설치본이라, 대시보드 한 줄을 고치고 번들을 재빌드하니 웹 섬 11개가 전부 옛 vue로 다시 만들어졌다 — 커밋 훅의 「재빌드 diff 0」 검사는 이걸 원리상 못 잡는다

**3회차(T-150·T-244 「옛 입력으로 빌드」 군)** / 증상: 회당 시간 최소 10분 PR(#1134)에서 `StudyTimerCard.vue`의 `min="1"`→`min="10"` 한 곳만 바꾸고 `npm --prefix frontend run build`를 돌렸는데 `src/main/resources/static`의 섬 번들 11개가 전부 바뀌었다(205줄±, 대시보드와 무관한 `block-list`·`history`·`profile` 등 포함). 변경 크기가 수정 범위와 안 맞아 알아챘다. / 원인: 이 워크트리의 `frontend/node_modules`(정션이 아닌 실폴더)가 dependabot #1129(vue 3.5.42·vitest 4.1.11·test-utils 2.5.0·playwright 1.63.0·sharp 0.35.4) **이전에** 설치돼 5개가 lock과 달랐다(vue 3.5.41 등). 섬 번들은 vue 런타임을 품어 옛 vue로 빌드하면 전부 바뀐다. 커밋 훅 `require-bundle-build.ps1`은 「재빌드 뒤 `static` diff가 있으면 차단」인데, 옛 설치본으로 **재빌드한 결과를 커밋하면** 훅의 재빌드도 같은 옛 설치본을 써서 diff 0 → 통과한다. CI(`npm ci` 후 「Verify bundle is not stale」)에 가서야 막히고, 그 전에 머지되면 #1129의 번들 재생성이 되돌아간다. / 해결: 번들을 `git checkout`으로 되돌리고 `npm --prefix frontend ci`(vue 3.5.42) 후 재빌드 → `dashboard.js` 한 줄(`min:"10"`)만 남음, 웹 vitest 772건 통과. / 재발방지: 훅이 재빌드 **전에** `node .claude/hooks/lib/deps-match-lock.js frontend`로 직접 의존성 설치본을 lock과 대조해 다르면 「이름: installed X != lock Y」와 `npm --prefix frontend ci` 안내로 차단(exit 2) — lock 없음·스크립트 오류는 fail-open. 대조를 node로 뺀 이유: PowerShell 5.1 `ConvertFrom-Json`은 lock의 루트 키 `""`(빈 이름)를 못 읽는다. 테스트 Case 8(옛 vue → exit 2 + 메시지)·9(일치 → exit 0, 기존 Case 5는 lock이 없어 이 경로의 양성 대조가 못 됐다) Red 2건 → Green, 돌연변이(`-eq 1`→`-eq 99`) 사살, 실제 배치 대조(이 워크트리 exit 0 · 메인 체크아웃 `frontend` exit 1 — lock에 있는 tiptap 8개 미설치). ⚠️ 정션으로 main의 `node_modules`를 쓰는 다른 워크트리는 main 설치본이 낡았으면 `frontend/` 커밋이 이 게이트에 막힌다 — 의도다(정션을 끊고 `npm ci`). / **관련**: T-244(같은 군 — 미니앱 `deploy.sh` ⓪, 파이썬 대조) · T-082·T-063(같은 훅이 막는 「소스↔번들 불일치」 반대 방향) · T-228(같은 훅 — 한 명령에서 `git add && git commit`하면 PreToolUse가 스테이징 전 인덱스를 봐 이번에도 오탐 차단이 났다, 명령을 나눠 해결) · 글로벌 「통과는 증거가 아니다」(재빌드 diff 0 ≠ lock대로 빌드).
