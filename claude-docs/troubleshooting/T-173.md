# T-173 · hookify `warn-multibyte-grep` 룰이 줄바꿈을 건너뛰어 한 세션에 5번 오탐 — 경고가 소음이 되면 진짜 발동을 무시하게 된다

증상: `grep`·`sed` 패턴이 **전부 ASCII** 인데도 룰이 반복 발동했다. 예: `sed -n '25,34p' file` + 다음 줄 `echo "=== 파일 끝 3줄 ==="` 조합. 한글은 grep/sed 와 무관한 `echo` 문자열이나 **출력**에만 있었다. 세션 중 6회 발동 중 **5회가 오탐**(진짜는 1회 — `grep "리뷰|보안|…"`). / 원인: 패턴이 `(?<!-)\b(grep|sed)\b[^|;&]*[^\x00-\x7F]` 인데 **`[^|;&]*` 가 개행을 배제하지 않는다.** 그래서 grep/sed 뒤의 «줄바꿈을 넘어» 다음·다다음 줄의 한글까지 닿는다. 파이프·세미콜론·앰퍼샌드로만 끊기니, 여러 줄짜리 명령에서는 사실상 **명령 전체에 한글이 하나라도 있으면** 발동한다. / 해결: 제안 = 배제 문자에 개행을 더한다 — `[^|;&\n]*`. 실제 한글 패턴은 `grep` 과 **같은 줄**에 있으므로 진짜 발동은 유지되고, 다른 줄 `echo` 의 한글은 더 이상 닿지 않는다. ⚠️ 룰 파일이 글로벌(`~/.claude/hookify/warn-multibyte-grep.md`)이라 수정은 그 설정 레포의 브랜치 절차로 별도 진행한다(이 레포 커밋으로 고칠 수 없다). / 재발방지: ① **hookify 룰을 만들 때 「명령이 여러 줄이면」을 반드시 시험한다** — 셸 명령은 한 줄이라는 암묵 가정이 이 룰의 유일한 결함이었고, `-Validate` 는 정규식 컴파일만 보지 오탐률은 안 본다. ② 룰 추가 시 **발동해야 하는 케이스 2~3건 + 침묵해야 하는 케이스 2~3건**을 실제로 돌려 본다(`warn-migration-schema-test` 는 5케이스를 실측해 이 문제가 없었다). ③ warn 룰이 반복 오탐하면 **끄는 게 아니라 좁힌다** — 소음이 쌓이면 진짜 발동을 흘려보내게 되고, 그게 룰이 없는 것보다 나쁘다. 1회차 신규
