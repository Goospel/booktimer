# T-162 · bash 인라인 `python -c "…"` 안의 백틱이 명령치환으로 실행돼 한글 문서 행이 조용히 훼손된다 — 에러는 나는데 파일엔 이미 망가진 행이 들어가 있다

증상: `claude-docs/changelog.md`에 한 줄을 추가하려고 python 인라인으로 문자열을 넘겼는데, 그 문장에 들어 있던 `` `login_id` `` 같은 **코드 백틱 부분이 사라진 채** 파일에 기록됐다. 셸이 에러를 뱉긴 했지만 파일 쓰기는 이미 일어난 뒤라, 에러만 보고 "실패했으니 파일은 그대로겠지"라고 넘기면 훼손된 행이 그대로 커밋된다. / 원인: bash에서 **큰따옴표 안의 백틱은 명령치환**(`` `cmd` ``)이다. 한글 산문과 코드 식별자가 섞인 문서 텍스트엔 백틱이 흔하게 들어가므로 정면충돌한다 — `` `login_id` ``가 "login_id라는 명령을 실행한 결과"로 치환되어 빈 문자열이 된다. 인용부호를 신경 써도 **내용이 백틱을 포함한다는 사실 자체**가 지뢰라, 값을 어떻게 감싸느냐로는 안 풀린다. / 해결: 문서 텍스트는 셸을 경유시키지 않는다 — 스크래치패드에 **Write 도구로 UTF-8 파일**을 만들고 그 파일을 읽어 붙이거나, 애초에 Edit 도구로 대상 파일을 직접 고친다. / 재발방지: ① **긴 한글·코드 혼합 텍스트를 셸 인라인 인자로 넘기지 않는다**(파일 경유 또는 Edit 도구). ② 셸을 꼭 거쳐야 하면 작은따옴표를 쓰고(백틱 비활성) 그래도 값 안에 작은따옴표가 있으면 파일 경유로 후퇴한다. ③ 인라인 문자열 조작이 에러를 냈을 때 **대상 파일을 반드시 다시 열어 본다** — 이 계열은 "에러 + 부분 기록"이 함께 온다. Windows 셸 인라인 인자군(T-026 한글 CP949 깨짐 · T-158 PowerShell 따옴표 소실·콤마 배열화)의 사촌 — 셋 다 **"인라인으로 넘긴 문자열이 그대로 도착하지 않는다"**가 뿌리고 변형만 다르다(인코딩 / 따옴표 / 명령치환). 이 군은 이미 `.commit-msg-tmp` 파일 경유 + `check-commit-message.ps1` 훅으로 승격돼 있으나 **그 승격물은 git 커밋 메시지만** 겨눈다 — 일반 문서 편집 경로는 여전히 prose가 유일 방어선이라, 같은 변형이 2회째 나오면 「셸 인라인에 백틱·따옴표 포함 한글 문자열」을 감지하는 hookify warn 룰로 승격 검토. 1회차 신규. 미니앱 핸들 만들기 문서 sweep 중 발생
