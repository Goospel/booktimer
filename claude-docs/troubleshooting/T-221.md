# T-221 · `git commit -F .commit-msg-tmp`가 이전 세션의 잔재 파일을 조용히 집어 옛 메시지로 커밋됐다 — 파일 경유 커밋은 「파일이 지금 내 것인가」를 묻지 않는다

**2회차(변종 — 2026-09-12 #1105 리뷰 반영 커밋, 아래 ⑥)** / 증상: 웹 「공부」 PR-1의 첫 커밋 제목이 이번 작업이 아니라 **이전 세션의 메시지**로 나갔다. 에러 0, 훅 전부 통과, 커밋 성공 — `git log`를 보고서야 알았다(push 전이라 `--amend`로 바로잡음). / 원인: `.commit-msg-tmp`를 heredoc으로 쓰는 명령이 다른 훅에 막혀 **통째로 실행되지 않았는데**, 이어진 `git commit -F .commit-msg-tmp`는 독립 명령이라 그대로 돌았다. 파일은 gitignore라 `git status`에 안 보이고, 이전 세션이 커밋 뒤 지우지 않은 잔재가 남아 있었다. `-F`는 파일의 **존재**만 보지 **신선도**는 안 본다 — 무성 실패다. / 해결: `git commit --amend -F <새 파일>`로 메시지 교체, 파일 삭제. / 재발방지: ① **쓰기 직전 `rm -f .commit-msg-tmp`** 후 새로 쓴다 ② **커밋 직후 삭제**한다 ③ 쓰기와 커밋을 **한 명령에 `&&`로 잇지 않는다** — 쓰기 명령의 성공을 본 뒤 별도 명령으로 커밋한다(막힌 명령 뒤에 커밋만 살아남는 구조 자체를 없앤다). 세 줄을 CLAUDE.md 「🈲 한글 커밋 메시지」 절차에 박았다(2026-09-03). 훅 승격은 보류 — 「이 파일이 이 세션 것인가」는 정규식 판정 대상이 아니라 hookify 룰이 안 맞고, 1회차라 전용 훅(예: `git commit` 뒤 파일을 지우는 PostToolUse)은 재발 시 검토. ⑥ **2회차(변종, 2026-09-12)**: 이번엔 잔재 파일이 아니라 **스테이징**이었다 — `git add -A && git commit -F .commit-msg-tmp`를 한 명령에 묶었는데 커밋 메시지 훅(`check-commit-message.ps1`)이 그 명령을 **통째로** 막아 `add`까지 안 돌았고, 이어 별도로 친 `git commit --amend`는 성공해 **changelog 중복 제거가 빠진 커밋이 push됐다**(뒤늦게 `git diff origin/main`으로 발견해 재커밋). 뿌리는 ③과 같다 — **훅이 막은 명령은 앞부분도 함께 죽고, 다음 명령은 그 사실을 모른다**. 그래서 규칙을 넓힌다: 「쓰기·스테이징·커밋을 한 명령에 묶지 않는다」 — `git add`도 커밋과 **별도 명령**으로 치고, 커밋 직전 `git status --short`로 스테이징을 눈으로 본다. 승격은 보류 — hookify warn 룰(`git add[^\n]*&&[^\n]*git commit`)은 정규식 한 줄로 되지만 이 변종은 hookify 도입 전엔 없던 조합이라 3회차에 검토. / **관련**: T-026(같은 파일을 쓰는 절차의 원점 — 인코딩 함정) · T-210(같은 세션 안에서 두 번 건드린 흔적이 조용히 남는 같은 부류 — 2회차의 빠진 dedup이 바로 T-210 처리분이었다)
