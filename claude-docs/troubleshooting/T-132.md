dependabot 프론트 dep bump 중 **런타임 번들에 인라인되는 것**(vue 등)은 lockfile만 올려 CI `Verify bundle is not stale`가 RED — vue 런타임은 각 섬 번들 JS에 인라인되는데(`@vue/* 버전 마커`가 `static/**/*.js`에 박힘) dependabot은 `src/main/resources/static/**` 번들을 재빌드·커밋 안 해 lock↔아티팩트 드리프트로 stale 게이트가 실패 / 감별=CI에서 test·build는 GREEN인데 "Verify bundle is not stale"만 RED이고 PR diff가 `package-lock.json`뿐이면 코드 회귀가 아니라 번들 미재빌드 / 해결=PR 브랜치 체크아웃→`npm ci`→`npm run build`→재생성 번들 커밋·push→머지(번들이 새 버전 반영해 stale 해소) / **대조**: vitest(테스트러너)·@vitejs/plugin-vue(빌드타임 SFC 컴파일러)는 서빙 JS에 안 실려 재빌드 없이 통과 — "그 major dep이 런타임 번들에 들어가나"가 stale 실패 여부를 가름(vue=인라인→RED / vitest·plugin-vue=미포함→GREEN). phaser처럼 죽은 dep도 미포함이라 통과하되 bump 무의미→제거(#656) / 2026-07-05 dependabot 프론트 PR 정리 #649(vue), T-063·T-082 번들 군·N-083, 1회차 신규
