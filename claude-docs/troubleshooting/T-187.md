# T-187 · `bootRun` 중에 고친 정적 리소스(css·js)가 화면에 안 나온다 — 서버가 `build/resources/main` 복사본을 해시 URL로 서빙한다

증상: `app.css`를 고치고 새로고침해도 옛 스타일 그대로였다. `curl http://localhost:8080/css/app.css`로 확인하면 **서버는 새 내용을 주는데** 화면만 안 바뀌어, 브라우저 캐시로 오해하고 캐시버스터(`?v=…`)를 붙여도 그대로였다. / 원인: 두 겹이다. ① `bootRun`이 서빙하는 실체는 `src/main/resources`가 아니라 **`build/resources/main` 복사본**이라, 소스를 고쳐도 `processResources`를 돌리기 전엔 반영되지 않는다. ② 템플릿이 참조하는 URL이 **콘텐츠 해시**(`/css/app-d8505b….css`)라, 파일을 갱신해도 페이지는 여전히 **옛 해시 경로**를 요청한다 — 그래서 `?v=` 캐시버스터가 무력하다(같은 옛 파일에 쿼리만 붙는 꼴). / 해결: 소스 수정 후 `./gradlew processResources`로 복사본을 갱신하고, **해시 URL 갱신까지 필요하면 `bootRun` 재시작**. 확인만 빠르게 할 땐 브라우저에서 링크를 해시 없는 원본 경로로 갈아끼우면 된다: `document.querySelectorAll('link[rel=stylesheet]').forEach(l => l.href = '/css/app.css?v=' + performance.now())`. / 재발방지: ① **"서버가 새 파일을 준다"를 반영의 증거로 삼지 않는다** — 확인할 것은 `curl /css/app.css`가 아니라 **페이지가 실제로 요청한 URL**(`[...document.styleSheets].map(s => s.href)`)이다. 해시가 그대로면 옛 파일이다. ② 정적 리소스를 만지는 검증 루프에선 **`processResources` → (해시가 걸린 경우) 재시작**을 한 쌍으로 기억한다. ③ 증상이 "브라우저 캐시 같다"인데 캐시버스터가 안 들으면 **캐시가 아니라 URL 자체가 다른 파일을 가리키는 것**을 의심한다. **2회차(2026-09-11 — #1098 구현·리뷰 중 각 1회)**: 이번엔 ①만 걸렸고 방향이 반대였다 — 소스 `app.css`를 고치고 e2e를 돌렸는데 6건이 그대로 실패해 「고친 게 안 먹었다」로 읽혔고, `./gradlew processResources` 뒤에야 GREEN이 됐다(**가짜 RED**). 원본은 「curl은 새 내용을 주는데 화면만 옛것」(② 해시)인데 이번은 **curl 자체가 옛 내용**이라 감별이 오히려 쉽다: `curl localhost:8080/css/app.css`에 방금 넣은 문자열이 없으면 복사본이 낡은 것이다. 승격 후보 = **스펙이 스스로 낡음을 큰 소리로 실패시키는 가드**(서빙 CSS와 소스의 지문을 대조해 불일치면 「processResources를 돌려라」로 실패). e2e npm 스크립트에서 gradle을 부르는 안은 bootRun과 빌드 락이 경합할 위험(T-078)이 있어 버렸다. ⚠️ **미검증** — 이 가드는 「`processResources`가 정적 리소스를 바이트 그대로 복사한다(토큰 치환 없음)」가 참이어야 성립하는데, 2026-09-12 확인 시도 때 Docker Desktop이 꺼져 bootRun이 안 떠서 못 쟀다. CHECK: Docker 기동 후 `bootRun` → 소스와 `build/resources/main/static/css/app.css` 바이트 비교. EXPECT: `equals()`가 true. **EVIDENCE: 2026-09-12 충족** — `processResources` 복사본도, HTTP 응답 본문도 소스와 **바이트 동일**(233081B, sha256 앞 12자 `5c77e141663e` 일치). 전제가 참이라 **가드를 넣고 승격했다**(`frontend/e2e/pencil-frame.spec.ts` 첫 테스트 「전제 — 서버가 서빙하는 app.css가 소스와 바이트 동일하다」). ⚠️ **판별력을 실측으로 못 박았다**: 소스에만 마커를 넣고 `processResources`를 일부러 건너뛴 「낡은」 상태에서 가드가 `소스 233109B 252c30b2374c / 서빙 233081B 5c77e141663e`와 처방을 찍으며 **1 failed**로 죽었고, **나머지 9건은 그 옛 CSS를 재고 초록이었다** — 가드가 없으면 그 9개의 초록이 그대로 「통과」로 읽힌다는 뜻이다. 마커를 걷고 `processResources` 후 10건 초록 복귀. 📍 이때 「Docker가 필요하다」고 적었던 것도 정정한다 — 전제 확인은 `processResources`(gradle)만 쓰고 Docker는 `bootRun`에만 필요하다. 두 단계를 묶어 과하게 제약했다. 2회차
