# T-186 · Windows aws CLI는 요청뿐 아니라 *응답*의 한글에도 죽는다 — `'cp949' codec can't encode`. 원격에서 base64로 싸서 받아라

증상: 운영 EC2의 「토스 재참여 넛지 배치 완료」 로그를 `aws ssm send-command`+`get-command-invocation`으로 조회하는데, 명령 JSON은 ASCII만 썼는데도 결과를 받는 순간 `'cp949' codec can't encode character` 로 CLI가 죽었다. 요청 쪽 함정(paramfile을 로컬 코드페이지로 읽어 `Unable to load paramfile ... could not be decoded`)만 알고 있으면 "요청엔 한글이 없는데 왜?"에서 막힌다. / 원인: 한국어 Windows의 aws CLI(Python)가 **stdout 인코딩을 콘솔 코드페이지(CP949)로** 잡는다. 조회 대상이 한글 로그라 응답 본문에 한글이 실려오고, 출력하는 순간 CP949로 인코딩 불가라 예외가 난다. 요청 방향(디코드 실패)과 **같은 뿌리의 반대 방향**(인코드 실패)이다. `PYTHONIOENCODING=utf-8` 로는 안 풀렸다. / 해결: **원격 셸 안에서 `base64 -w0` 로 싸서 받고 로컬에서 디코드**한다 — CLI가 만지는 바이트가 전부 ASCII가 되어 방향을 안 탄다. 디코드한 뒤의 한글 필터링은 ripgrep(Grep 도구)이나 PowerShell 리터럴로 한다(Git Bash grep은 한글을 에러 없이 0건 처리하는 무성 실패). / 재발방지: **aws CLI와는 ASCII만 주고받는다** — 요청은 한글 금지, 응답은 base64 왕복. 한글 로그를 뒤지는 SSM 조회 자동화는 처음부터 이 경로로 짠다. Windows 셸 인라인 인자군(T-026 커밋 메시지 CP949 · T-158 PowerShell 따옴표 · T-162 백틱 명령치환)의 사촌이되, 저 셋이 **나가는** 문자열이 안 도착하는 문제라면 이건 **들어오는** 문자열이 못 나오는 문제다. 2회차(요청 방향은 정기작업 지시서에 선기록) — 정기작업 「토스 재참여 넛지 19시 배치 로그 확인」 첫 실행 중 발생
