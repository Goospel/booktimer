# T-276 · 기기 확인 중 운영 본인 계정이 탈퇴로 지워졌다

## 증상

PR-P③ 기기 확인 마지막 항목(v1 §4.3 ⑥)은 「id 17로 설정 → 계정 삭제 화면을 열어 [구글로 확인하고 지우기] · 문구를 **누르지 않고** 사진」이었다.
2026-10-27 11:52~11:53 KST, 단추가 눌려 구글 재확인 → Apple 창 한 번 더 → 서버 탈퇴(`AccountService.purge`)가 끝까지 돌았다.
웹에 다시 로그인하자 「계정을 지웠어요」가 떴다. 그 계정은 웹 · 앱 공용 운영자 본인 계정이었고, 독서 기록 641개, 서재 27권 등이 있었다.

## 원인

- 확인 절차 설계가 되돌릴 수 없는 단추 바로 앞에 대체 불가능한 계정을 세웠다. 「누르지 않는다」는 산문뿐이었고, 화면에는 그 단추 하나가 크게 있었다.
- 앱은 설계대로 동작했다. 재인증이 곧 확인 단계라서, 한 번 누르고 구글 창을 통과하면 지워진다.
- 운영 MySQL은 `--disable-log-bin`이라 시점 복구가 안 된다. 되살릴 길은 `deploy/backup-mysql.sh`의 하루 1회 S3 백업(7일 보존)뿐이었다.

## 해결

같은 날 2026-10-26T18:00Z 백업에서 그 계정의 행만 되살렸다.

1. 로컬 mysql:8.4에 백업을 풀고, purge가 지우는 표 26개를 코드(`AccountService.purge`)와 FK로 대조해 13개 표 844행을 추렸다. 로그인 토큰은 뺐다.
2. 한 트랜잭션 INSERT 파일을 만들어 로컬에서 리허설했다. 중간 실패 시 0행, 표 하나를 빼면 그 표만 어긋남을 확인했다. 독립 리뷰 2회를 거쳤다.
3. 운영에서 읽기 전용 사전 확인(신원 · PK 충돌 · 다른 사용자 행 수)을 33/33 통과시켰다.
4. 사용자 승인 뒤 SSM으로 조각 전송 → sha256 게이트 → 실행했다.
5. 사후 확인 24/24 뒤, 사용자가 웹 · 아이폰에서 서재 27권을 확인했다.

잃은 것은 그날 03:00~11:53 사이 독서 기록 최대 3개와 그 사이의 수정이다.

## 재발 방지

- 미검증 가정의 `CHECK:`가 탈퇴 · 삭제 · 발송처럼 되돌릴 수 없는 동작에 닿으면 **버리는 계정으로만** 짠다. 본 계정은 「보기만」으로도 그 화면에 세우지 않는다(CLAUDE.md 가드 줄).
- 그 계정 갈래(예: 구글 가입 + Apple 연결)를 버리는 계정으로 만들 수 없으면, 문구는 상수 테스트로 잠그고 화면 사진은 `ABANDON`으로 드러낸다. 이번 v1 §4.3 ⑥ 문구 사진도 그렇게 남겼다.
- 곁가지: 같은 복구 준비에서 `backup-mysql.sh`의 두 번째 덤프에 `USE booktimer`가 없는 결함이 드러났다. 통째로 적재하면 세션 표가 facefit에 생긴다. 같은 날 따로 고쳤다(T-275 · 백업 통째 적재 테스트가 CI에서 지킨다).
