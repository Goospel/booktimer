# T-247 · 하위 스코프에서 토큰을 다시 깔아도 이미 계산된 값은 안 바뀐다 — 상속 프로퍼티(`color`)와 `var()` 별칭은 「선언된 요소」에서 한 번 계산돼 내려온다

**1회차** / 증상: 공부 측정 중 화면을 어둡게 하는 독서등(`body.study-lamp`)을 넣고 불빛 밑 카드(`.lamp-page`)에만 낮 토큰을 다시 깔았다. 규칙은 분명히 들어가 있는데 ① 밝은 카드지 위 글자가 밤 색 그대로라 안 보였고(시안 단계) ② 라이트 테마에서 왼쪽 바 hover 배경이 낮의 연녹 `#E7EEE2`로 남아 밤 바 위 글자 대비가 **1.09**였다(PR #1144 독립 리뷰 실측). 둘 다 「토큰을 다시 깔았으니 따라오겠지」가 틀린 자리다. / 원인: 커스텀 프로퍼티는 **선언된 요소에서** 계산되고 자식은 그 계산값을 물려받는다. ① `color`는 상속 프로퍼티라 `body`에서 밤 토큰으로 계산된 값이 그대로 내려온다 — 자식에서 `--text`만 낮 값으로 되돌려도 이미 계산된 `color`는 안 바뀐다. ② `--nav-hover-bg: var(--sage-soft)` 같은 **별칭**은 `:root`에서 라이트 값으로 굳어 상속되므로, `body`에 얹은 밤 팔레트가 `--sage-soft`만 뒤집어도 별칭은 `:root` 계산값 그대로다. 다크 테마는 `:root[data-theme="dark"]`라 같은 요소에서 다시 계산돼 **저절로 따라오던** 것이고, 독서등만 `body`라 여기서 갈렸다 — 「원래 되던 규칙」이라 의심이 늦었다. / 해결: 스코프 블록에 **상속 프로퍼티를 다시 선언**하고(`body.study-lamp .lamp-page { color: var(--text); }`) **별칭도 그 블록에 다시 적는다**(다크·독서등 목록에 `--nav-hover-bg: var(--sage-soft);` 추가 — hover 대비 1.09 → 9.26). / 재발방지: ① 「토큰을 다시 깔았다」는 「값이 바뀐다」가 아니다 — 스코프를 좁혀 팔레트를 뒤집을 땐 **상속 프로퍼티**와 **`var()` 별칭** 두 종류를 따로 센다. ② 계측기는 `frontend/src/darkTokens.test.ts`(라이트↔다크 토큰 짝을 양방향으로 센다)다 — 2026-09-16 돌연변이 실측으로 확인했다: 다크 목록에서 `--nav-hover-bg` 한 줄을 지우자 193행 단언이 붉어졌다(양성 대조군이 있는 검사). ③ 판정은 클래스가 붙었는지가 아니라 `getComputedStyle`의 최종값으로 한다. / **관련**: T-035(같은 「분명히 적었는데 안 먹는다」 군의 다른 축 — cascade origin) · 글로벌 「통과는 증거가 아니다」.
