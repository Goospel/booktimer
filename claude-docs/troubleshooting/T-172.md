# T-172 · `sed -i`를 `find -exec`로 돌리면 패턴이 안 맞는 파일까지 전부 다시 쓴다 — 줄끝이 조용히 뒤집힌다

증상: 스크립트 태그 13개에 nonce를 붙이려고 `find src/main/resources/templates -name '*.html' -exec sed -i 's|…|…|g' {} +` 를 돌렸는데, 직후 `git status` 에 **손댄 적 없는 템플릿까지 `M`** 으로 떴다(`admin.html`·`error.html`·`landing.html`·`login.html` 등, 총 42개). / 원인: `sed -i` 는 **매치 여부와 무관하게 모든 입력 파일을 다시 쓴다**(임시파일에 출력 후 rename). Git Bash 의 sed 가 쓰는 줄끝은 LF 라, CRLF 로 체크아웃돼 있던 파일이 전부 LF 로 바뀌어 git 이 변경으로 본다. 치환은 0건인데 파일은 100% 재작성되는 것 — 명령은 성공으로 끝나 아무 신호가 없다. / 해결: 이번엔 `git add -A` 시 `core.autocrlf` 정규화가 흡수해 **스테이징엔 의도한 변경만** 남았다(`git diff --cached --numstat` 로 파일당 1~4줄임을 확인해 사고 아님을 확정). / 재발방지: ① **다중 파일 치환은 `sed -i` 대신 Edit 도구**(대상만 연다)나 파일별 루프 + 매치 확인. 굳이 sed 를 쓸 거면 `grep -l` 로 **매치되는 파일만 골라** 넘긴다. ② 대량 치환 직후엔 `git status` 가 아니라 **`git diff --numstat`** 으로 «파일당 변경 줄 수» 를 본다 — 상태만 보면 EOL 재작성과 실제 변경이 구분되지 않는다. ③ 이 레포는 `core.autocrlf` 가 받아 줬을 뿐이고, `.gitattributes` 나 정규화가 없는 레포였다면 42파일 phantom diff 가 그대로 커밋된다. **3회차**(T-093 · T-103 재발) — 앞선 2회의 승격(「우리가 짜는 재생성기는 BOM·EOL 을 보존한다」는 코드 패턴)은 **남이 만든 도구엔 걸 자리가 없어** 이번을 못 막았다
