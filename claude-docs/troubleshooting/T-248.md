# T-248 · 쉘 리다이렉트 토큰이 git 위치 인자로 읽혀 fail-closed 게이트가 멀쩡한 명령을 막는다 — `2>&1`이 `<branch>` 자리에 앉았다

**1회차(실전) + 재현 시도에서 1회 더** / 증상: 리베이스 명령 꼬리에 `2>&1 | tail -8`을 붙여 돌리자 `require-single-changelog-commit-before-rebase.ps1`이 **`[BLOCKED] … 대상 브랜치 '2>' 과 'origin/main' 의 merge-base 를 구할 수 없습니다`**로 막았다(2026-09-15 10:09, PR-2 리베이스). 그 브랜치는 changelog를 한 커밋에서만 건드려 원래 통과해야 하는 모양이었다. 2026-09-16엔 이 함정을 재현하려고 만든 명령 **자체가** 같은 이유로 막혔다(훅은 Bash·PowerShell 명령 문자열을 본다). / 원인: 훅이 `rebase` 뒤 인자를 `[^;&|\r\n]*`로 캡처해 `origin/main 2>`까지 받고(`&`에서 잘린다), `-`로 시작하는 옵션만 걸러 나머지를 위치 인자로 센다 — `2>`는 `-`로 시작하지 않아 **둘째 위치 인자 = `<branch>`**가 된다. 이어지는 `merge-base '2>' origin/main`이 실패하는데, 이 훅은 T-210이 7회 샌 뒤라 **판정 불가를 fail-open이 아니라 차단**으로 정해 뒀다 — 설계대로 동작한 오탐이다. / 해결: 위치 인자 파서가 리다이렉트 토큰을 건너뛴다(`^[0-9&]*(>>?|<)`, 연산자만 따로 선 `> out.txt`는 그 뒤 파일명까지). 테스트 3건 추가 — `2>&1 | tail` 통과 · `> out.txt` 통과 · **같은 리다이렉트를 붙인 T-210 모양(changelog 2커밋)은 여전히 차단**. 마지막 건이 「리다이렉트를 우회로 만드는」 구현을 배제한다. Red 2건 확인 후 Green, 스위트 38건 전부 통과. / 재발방지: ① 명령 문자열을 파싱하는 훅은 **쉘 문법(리다이렉트·꼬리 파이프)을 먼저 걷어낸 뒤** git 인자를 센다. ② **fail-closed 게이트일수록 「정상 명령이 통과하는가」 대조군을 같이 둔다** — 판정 불가를 차단으로 정한 순간, 파서가 조금만 헐거워도 그 값은 오탐 차단으로 나온다(이 훅의 테스트 35건은 전부 「막아야 할 것을 막는가」 쪽이었다). ③ 하드픽스로 닫혀서 재발·승격 트래커에는 올리지 않는다. / **관련**: T-242·T-228(같은 훅군의 **반대 방향** — 명령의 실제 대상이 훅의 관점 밖이라 조용히 통과) · T-210(이 게이트가 선 이유) · 글로벌 「통과는 증거가 아니다」(여기선 거꾸로 — 차단이 「위반의 증거」가 아니다).
