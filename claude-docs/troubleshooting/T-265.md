# T-265 · 스택 PR의 아래 PR에 커밋을 더하면 위 브랜치가 그것을 못 받는다

## 증상

- 에디토리얼 재테마 PR-1 #1245 → PR-2 #1246 → PR-3 #1247 → PR-4 #1248을 서로 위에 쌓았다.
- PR-2는 PR-1의 `4fdd0ce9`에서 갈라졌다. 그 뒤 PR-1에 리뷰 low 반영 커밋 `3d97a5df`(그림자 가드 · 검정 알약 셈)가 더해졌다.
- PR-2·3·4는 이 커밋 없이 구현·리뷰됐다. PR-4는 그 가드를 넓혀야 해서 테스트 파일 3개만 cherry-pick했고, 이 때문에 나중에 병합하자 `typography.test.tsx`가 충돌했다.
- GitHub는 네 PR을 모두 CLEAN으로 보였다. 각 PR이 자기 base 브랜치하고만 비교하기 때문이다.

## 원인

- 스택은 아래 브랜치의 그 시점 머리 위에 위 브랜치를 쌓는다. 아래 브랜치가 앞으로 나가도 위 브랜치는 저절로 따라가지 않는다.

## 해결(2026-10-13 실행)

1. 아래부터 차례로 병합해 스택을 맞췄다: PR-1 머리 → PR-2(`c085d796`) → PR-3(`07d01397`) → PR-4(`a457a551`).
2. PR-1을 squash 머지한 뒤, PR-2를 PR-1의 옛 머리 `3d97a5df` 기준으로 `git reset --soft` → 한 커밋 → `git rebase --onto origin/main 3d97a5df` → `--force-with-lease`로 옮겼다.
3. PR-3(기준 `c085d796`)·PR-4(기준 `07d01397`)도 같은 꼴로 옮겼다. 매번 main 트리가 합친 커밋의 부모 트리와 같아서 충돌이 0이었다.
4. changelog를 여러 커밋에서 건드린 브랜치도 한 커밋으로 합쳐지므로 T-210 게이트를 통과한다.

## 재발 방지

- 아래 PR에 커밋할 때마다 위 브랜치에 병합한다. 커밋 직후 `git merge-base --is-ancestor`로 위 브랜치마다 확인한다.
- 아래 PR이 머지되면 위 브랜치를 옮기기 전에 `git diff --quiet <합친 커밋의 부모> origin/main`으로 트리가 같은지 먼저 본다. 같으면 rebase는 충돌 없이 끝난다.
