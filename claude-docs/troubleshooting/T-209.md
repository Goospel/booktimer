# T-209 · 돌연변이 확인의 되돌리기를 `git checkout --`로 하면 미커밋 작업분이 통째로 사라진다 — 「돌연변이만 되돌린다」는 직관이 틀렸다

증상: 새 기능(측정 시작 토스트·바꾸기 시트 — 같은 작업이 다른 세션에서 병행돼 결국 그쪽이 머지됐다)의 계측기를 검증하려고 돌연변이 스크립트를 돌렸다(코드 한 줄 죽이기 → 테스트가 붉어지나 → `git checkout --`로 원복, 반복). 첫 반복에서 스크립트가 **콘솔 인코딩 에러**로 죽었고, 남은 돌연변이 잔재를 치우려 손으로 `git checkout -- miniapp/src/App.tsx`를 불렀다. 그 순간 **그 파일의 미커밋 작업 약 200줄이 통째로 사라졌다** — 잔재 한 줄을 지우려던 명령이 그날 그 파일에 만든 것을 전부 지웠다. / 원인: `git checkout -- <path>`의 기준점은 **「내 실험 전」이 아니라 「마지막 커밋」**이다. 돌연변이는 작업분 **위에** 얹히므로, 그것을 걷는 명령이 그 아래 작업분까지 함께 걷는다. 「원복」이라는 말이 두 가지를 가리키는데(돌연변이 원복 / 커밋 상태 원복) git은 늘 뒤엣것을 한다. 곁다리로 판을 더 키운 요인이 둘 있다 — ① 스크립트가 파일을 다시 쓰며 **개행을 CRLF→LF로 바꿔**(newline 미보존) 이후 앵커 매칭이 전부 빗나갔고, 그게 「왜 앵커가 없지」로 시간을 더 먹었다(EOL 군 4회차) ② `subprocess`의 기본 디코딩이 CP949라 vitest의 한글 출력에서 죽었다(Windows 셸 원칙 2번의 사촌 — 이번엔 출력 방향). / 해결: **돌연변이는 커밋 뒤에 돌린다.** 그러면 `git checkout --`가 정확히 「돌연변이 전 = 커밋 상태」로 되돌아 의미가 하나가 된다. 스크립트 첫 줄에 `git status --porcelain`이 비었는지 보고 더러우면 즉시 종료하는 **청결 가드**를 넣었고, 파일 쓰기는 `newline=''`로 원본 개행을 보존하며 앵커의 `\n`을 파일 개행으로 변환해 찾는다. 복구는 그 편집들이 **대화에 남아 있어서** 가능했다(재적용 후 1042건 그린·tsc 클린으로 동일성 확인). 그 뒤 돌연변이 7종을 다시 돌려 전부 RED를 확인했다. / 재발방지: ① **미커밋 상태에서 `git checkout -- <path>`를 「실험 되돌리기」로 쓰지 않는다.** 실험 전에 커밋하거나(권장) `git stash push -- <path>`로 되돌릴 것을 명시적으로 집는다. ② 되돌리기를 자동화하는 스크립트엔 **작업 트리 청결 가드**를 넣는다 — 사람은 「커밋했나?」를 잊지만 스크립트는 안 잊는다. ③ **대화가 유일한 백업인 상태를 오래 두지 않는다** — 작업 덩어리가 끝나면 커밋한다. 이번엔 그 덩어리가 「구현 + 브라우저 검증」으로 길어서 노출 창이 컸다. ④ ⚠️ 이 함정은 **CLAUDE.md가 상시 권하는 절차(돌연변이 확인) 안에** 있다 — 절차를 따를수록 밟는다. ⑤ ⚠️ 곁다리 하나가 더 아프다 — **EOL 미보존은 이미 hookify warn 룰**(`warn-inplace-replace-crlf`)**로 승격돼 있고, 그 룰 본문은 「돌연변이 확인에서 이게 치명적이다」까지 적어 뒀는데도 못 막았다.** 패턴이 `sed|perl … -i`와 PowerShell `.Replace(…)…Set-Content` 둘뿐이라 **python 일회용 스크립트가 그 그물 밖**이었다. 좋은 룰이 있어도 **그 정규식이 지금 내가 쓰는 도구를 안 덮으면 없는 것과 같다** — 룰의 존재를 안심의 근거로 삼지 않는다. 1회차 신규(EOL 미보존 곁다리는 T-093·T-103·T-172 군 4회차)
