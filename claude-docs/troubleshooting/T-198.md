# T-198 · TDS `Text` 는 style 의 `text-align` 을 걸러 낸다 — 정렬이 에러 없이 죽는다

증상: 기록 화면 하루 줄을 고정 격자로 바꾸며 시간 칸에 `style={{ textAlign: 'right' }}` 를 줬는데 **왼쪽 정렬 그대로**였다. 콘솔은 조용하고 타입도 통과한다(`CSSProperties` 에 있는 속성이니까). `display: 'block'` 을 더해 봐도 안 먹었다. / 원인: TDS `Text` 가 `style` prop 을 **그대로 넘기지 않고 걸러서** 넘긴다 — 렌더된 span 의 인라인 스타일에 `white-space` 와 `display` 는 실렸는데 `text-align` 은 **아예 없었다**(computed 는 `start`). 즉 「내가 준 스타일이 DOM 에 도달했는지」가 컴포넌트 구현에 달려 있고, 소스만 읽어서는 어느 속성이 살아남는지 알 수 없다. / 해결: 정렬은 **감싸는 평범한 요소**가 한다 — `<div style={{ textAlign: 'right' }}><Text …/></div>`. 격자 칸이 그 div 이므로 칸 폭 안에서 인라인 콘텐츠가 정렬된다. / 재발방지: TDS 컴포넌트에 준 스타일이 안 먹으면 **소스를 다시 읽지 말고 렌더된 요소의 `getAttribute('style')` 을 본다** — 거기 없으면 걸러진 것이고, 그 순간 답은 「감싸서 하기」다. 그리고 이런 결함은 단위 테스트가 원리상 못 잡는다(마크업에도 그 속성이 안 찍히니 단언할 대상 자체가 없다) — **실 브라우저에서 글자의 실제 좌표를 재야** 보인다(`Range.getBoundingClientRect`; 칸의 `getBoundingClientRect` 는 정렬과 무관하게 늘 같아서 증거가 안 된다). **관련**: T-144(TDS 가 주입하는 CSS 때문에 정적 마크업 단언이 공허해짐) — 둘 다 「TDS 를 거치면 소스와 DOM 이 다르다」는 한 뿌리다.
