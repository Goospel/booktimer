# T-149 · 정적 렌더(`renderToStaticMarkup`) 하니스는 effect·이벤트를 안 돌리므로 "호출하지 않는다"류 카운트 단언은 항상 통과 — 구조적으로 공허한 테스트

증상: 심사 반려 대응(인트로 페이지)에서 "진입 시 자동 로그인을 호출하지 않는다"를 login mock 호출 카운트 0으로 검증하려던 계획이, 자동 로그인이 살아 있어도 항상 통과한다 — `renderToStaticMarkup`은 `useEffect`를 실행하지 않아 어느 쪽이든 카운트가 0이다(이번엔 구현 세션이 작성 전에 알아채 사고 없이 회피). / 원인: 이 하니스의 알려진 한계(jsdom 미도입 — onClick·effect 미실행)가 **부정 단언("안 한다")**과 만나면, 검증하려는 실패 모드 자체가 계측기의 관측 불가 영역에 정확히 들어간다 — T-145(매처가 그 실패를 안 매칭)와 같은 구조. / 해결: 관측 가능한 대체 신호로 번역해 계측 — "첫 렌더가 인트로 화면인가"(자동 로그인이 살아 있으면 초기 상태가 checking이라 로딩 마크업이 나온다). 돌연변이(자동 로그인 복원 → 3건 RED)로 판별력을 실측했다. / 재발방지: ① 정적 렌더 하니스에서 effect·핸들러 내부 동작에 대한 **부정 단언 금지** — 상태·마크업 차이로 번역해 계측한다 ② "안 한다" 검증은 그 실패를 실제로 만들어(돌연변이) 테스트가 깨지는지 확인한 뒤에만 신뢰한다. ③ **관측 불가 영역에서는 돌연변이의 침묵이 어느 쪽 근거도 못 된다**(2026-09-22 추가 — #1186·#1187): 「`load()`의 탭 초기화 줄이 실제로 일하는가」를 놓고, 리뷰가 **그 줄을 전부 지워도 미니앱 1688건이 통과한다**는 것을 근거로 구현자의 목 모드 관측(「남의 책방 필터가 내 책방에 남더라」)을 반박했다. 그러나 **#1187(T-256)이 관측 쪽이 옳았음을 확정**했다 — React가 키 없는 최상위 프래그먼트를 배열로 풀어 맞춰 두 분기의 `<Profile>`이 같은 fiber로 이어졌던 것이고, **재마운트 여부는 이 하니스가 원리상 계측하지 못한다**. 즉 그 침묵은 「일한다」의 근거도 **「무의미하다」의 근거도** 아니었다. ①②가 「부정 단언 → 거짓 초록」이라면 이쪽은 **무커버를 판정의 근거로 승격**한 것으로, 뿌리는 같고 방향만 반대다. ⚠️ 관측 불가 영역은 돌연변이가 아니라 **목 모드 실측**으로 판정한다(T-256이 그 게이트를 명시). 「공허한 테스트」군 **3회차**(T-144·T-145) — 트래커 갱신. 미니앱 심사 반려 대응 중
