# T-208 · `pr-merge.sh`를 못 쓰는 환경에서 auto-merge만 걸면 BEHIND 점검이 빠져 무한 대기 — T-111의 하드픽스가 `gh` CLI에 묶여 있어 원격(웹) 세션에선 증발한다

**8회차(T-111 재현 — 그때 만든 승격 산출물을 이번엔 *쓸 수 없어서* 밟았다)** / 증상: 개선안 노트 PR(#939)에 GitHub MCP `enable_pr_auto_merge`(SQUASH)를 걸고 떠났는데 27분 뒤에도 안 머지돼 있었다. 그새 `main`이 다른 세션의 PR 3개(#936·#937·#938)로 **23커밋 앞서** 브랜치가 BEHIND가 됐고, CI는 전부 그린인데 `mergeable_state: blocked`로 멈춰 있었다. / 원인: 이 레포는 「머지 전 브랜치 최신화 필수」 + auto-update off라 **BEHIND면 `--auto`가 영영 발화하지 않는다**(T-111 그대로). T-111이 만든 승격 산출물 `pr-merge.sh --arm`은 BEHIND를 1회 점검해 `gh pr update-branch`로 풀어 주는데, **그 스크립트는 `gh` CLI 전제**다. 이 세션은 `gh`가 없는 원격 환경(Claude Code on the web)이라 GitHub MCP 도구로 갈아탔고, 그러면서 **스크립트가 대신 해주던 BEHIND 점검 스텝이 통째로 빠졌다**. 하드픽스는 멀쩡한데 **실행 환경이 바뀌어 하드픽스가 있는 경로를 안 지나간 것**이다. / 해결: 브랜치를 최신 `origin/main` 위에 다시 얹고(`git checkout -B <branch> origin/main` 후 변경 재적용) `--force-with-lease` push → base가 최신이 되자 blocked가 풀리고 auto-merge가 살아 있어 CI 통과 후 발화했다. ⚠️ 이때 나는 changelog 끝줄 충돌을 우려해 재적용을 골랐는데 **불필요했다** — `.gitattributes`의 `claude-docs/changelog.md merge=union`(T-098 하드픽스)이 양쪽 새 행을 자동 병합하므로 **평범한 rebase로 충분했다**. 레포에 이미 깔린 하드픽스를 잊고 더 무거운 길을 고른 셈이라, 이것도 같은 군의 증상이다. / 재발방지: ① **auto-merge를 거는 것만으로 「걸고 떠나기」가 완성되지 않는다** — 건 직후 `mergeable_state`를 1회 점검하고 BEHIND면 풀어 줘야 `--arm`과 동등하다. `gh`가 없으면 MCP `update_pull_request_branch`가 그 자리를 대신한다. ② ⚠️ **승격 산출물이 특정 도구에 묶여 있으면 그 도구가 없는 환경에서 방어가 0이 된다** — CLAUDE.md가 「표준 경로」로 지정한 스크립트라도 먼저 **이 환경에서 실행 가능한가**를 확인하고, 불가능하면 그 스크립트가 하던 **스텝을 손으로 재현**한다(자동으로 면제되지 않는다). ③ 원격(웹) 세션엔 `gh`도 PowerShell 훅(`require-tests-before-commit.ps1` 등)도 없다 — 이 레포 하드픽스의 상당수가 안 붙는다는 것을 **세션 초반 전제로 깔고** 절차를 손으로 밟는다. / **관련**: T-111(6회차, BEHIND 무한대기 원본) · T-102(5회차, 하드픽스를 안 쓰고 손수) · T-098(changelog merge=union)
