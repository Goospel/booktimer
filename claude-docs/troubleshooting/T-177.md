# T-177 · 맨 `<button>`의 UA 기본 글자색이 iOS에서는 시스템 블루다 — 데스크톱 크롬은 검정이라 목 모드로는 원리상 못 잡는다

증상: 실기기 영상에서 책방 3열 격자의 **책 제목이 파랗게** 떴다(프레임 픽셀 실측 `#6590AE` = 크림 배경에 안티에일리어싱된 iOS 시스템 블루). 의도한 색은 본문 잉크이고, 같은 화면을 데스크톱 크롬 목 모드로 열면 검정으로 보인다 — 그래서 구현·리뷰·브라우저 검증이 전부 통과시켰다. / 원인: 격자 칸이 `<button>`인데 `color`를 안 줬다. **WebKit UA 스타일시트의 버튼 기본 글자색이 iOS에서 시스템 블루**라, 그 안의 TDS `Text`(`color` 프롭 없음)가 그대로 물려받는다. Blink는 같은 자리를 `buttontext`(검정)로 그린다 — **엔진별 UA 기본값 차이**라 코드에는 아무 흔적이 없고 정적 검사로도 안 보인다. 같은 형태가 친구 찾기 결과의 닉네임 줄에도 있었다(역시 맨 버튼 안의 `Text`). / 해결: 호출부마다 `color`를 적는 대신 `miniapp/src/global.css`에 `button { color: inherit }` 한 줄. 맨 버튼은 격자 칸·캐러셀 칸·목록 줄로 계속 늘어나 호출부 규약으로는 못 지킨다. 선택자를 **딱 `button`(0-0-1)**으로 둬야 TDS Button(자기 클래스로 색을 잡는다)이 안 밀린다 — 목 모드에서 primary(흰 글자)·weak(세이지 글자)가 그대로이고 격자 제목만 잉크로 바뀐 것을 computed style로 확인했다. / 재발방지: (1) **UA 기본값에 기대는 자리(맨 `<button>`·`<input>`·`<select>`)는 엔진마다 다르다고 보고, 색·폭·모서리를 명시하거나 전역 리셋으로 상속시킨다** — 웹 앱에서 이미 폭·모서리 면으로 세 번 밟은 자리다(T-056·T-081·T-099. 그쪽은 author 규칙 누수, 이쪽은 UA 기본값 누수로 방향만 반대다). (2) **iOS 고유 렌더링은 데스크톱 크롬으로 검증 불가**다 — 실기기(또는 실기기 영상)만이 계측기다. (3) 실기기 영상은 눈으로만 보지 말고 **프레임을 픽셀로 재라** — 「파랗다」는 인상을 색값으로 확정한 것이 UA 기본값이라는 원인에 닿은 경로였다. **4회차 = T-053·T-054·T-176 재발군**(검증 환경이 실환경보다 관대하면 그 클래스는 가짜 green으로 통과한다 — 이번엔 성능이 아니라 엔진별 UA 기본값 축) — 트래커 갱신
