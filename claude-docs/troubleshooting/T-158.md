# T-158 · PowerShell에서 k6에 부하 곡선을 넘기다 세 층에서 연달아 깨진다 — `K6_` 접두사는 k6가 선점하고, PowerShell은 큰따옴표를 벗기고 콤마를 배열로 쪼갠다

증상: 강도를 단계적으로 올리려고 스크립트의 `stages`를 환경변수로 파라미터화했는데 세 번 연속 다른 이유로 실패했다 — ① `-e K6_STAGES='[{"duration":"15s","target":1}]'` → k6가 `envconfig.Process: assigning K6_STAGES to Stages: converting … invalid duration "[{\"duration\""` 로 즉사(스크립트는 실행조차 안 됨) ② 이름만 `LOAD_STAGES`로 바꾸니 이번엔 스크립트 안에서 `SyntaxError: invalid character 'd'`(JSON.parse 실패) ③ JSON을 버리고 `-e LOAD_STAGES=1m:10,2m:30,2m:60` 로 바꾸니 k6가 `accepts 1 arg(s), received 4`. 매번 에러 메시지가 달라 원인이 하나로 안 보인다. / 원인: 세 실패의 층이 전부 다르다. ① `K6_*`는 **k6 자체 설정 네임스페이스**라 스크립트에 닿기 전에 k6의 envconfig가 먼저 파싱한다 — 하필 `stages`는 실재하는 k6 옵션이라 이름이 정면충돌했다. ② PowerShell 5.1이 native exe에 인자를 넘길 때 **값 안의 큰따옴표를 벗겨** `[{duration:15s,target:1}]`가 되어 JSON이 깨졌다 — 글로벌 CLAUDE.md 「PowerShell 인라인 인자」 함정의 **비-한글 판**(인코딩이 아니라 따옴표 소실). ③ 따옴표로 감싸지 않은 값에 콤마가 있으면 PowerShell이 그걸 **배열 리터럴**로 해석해 인자 하나를 4개로 쪼개 넘긴다. / 해결: ① 커스텀 환경변수는 `K6_` 접두사를 피한다(도구가 예약한 네임스페이스를 빌리지 않는다) ② 값에 따옴표·콤마가 있으면 **인자 전체를 PowerShell 문자열로 감싼다** — `-e "LOAD_STAGES=1m:10,2m:30"` ③ 애초에 **따옴표가 필요 없는 포맷**(`1m:10,2m:30` → `split(',')`+`split(':')`)으로 설계해 깨질 층을 하나 줄인다. JSON은 이 경로에서 비용만 크다. / 재발방지: ① 부하 곡선처럼 **실행마다 바뀌는 값**은 레포 스크립트를 고치지 말고 스크래치패드 복사본에서 파라미터화한다(원본 `load-test/booktimer-load.js`는 무변경 유지). ② PowerShell→native exe 인자는 "값에 따옴표·콤마·공백 중 하나라도 있으면 통째로 `"..."` 로 감싼다"를 기본값으로 삼는다. 1회차 신규 — 뿌리(=PowerShell이 인라인 인자를 그대로 안 넘긴다)는 T-026군과 같지만 그쪽 승격물(`.commit-msg-tmp` 파일 경유·`check-commit-message.ps1` 훅)은 **한글 인코딩만** 겨눠서 이번 따옴표·콤마 변형을 못 잡는다 — 같은 변형이 2회째 나오면 그때 군을 만들어 hookify warn(예: `-e`/`--arg` 뒤 따옴표 없는 콤마 값 감지)으로 승격 검토. 재발·승격 트래커 미등록. 트래픽 용량 실측(k6 부하 테스트) 중 발생
