# T-229 · 돌연변이 「생존」을 단일 파일 실행으로 판정하면 조용히 과대·과소 보고된다 — 계측기는 파일 경계를 모른다

**1회차** / 증상: PR #1043 구현 보고가 「M8(`untaggedSessionId` 정규화 제거)이 11건 전부 생존」이라 적었는데, 리뷰어가 **전체 스위트**로 다시 재니 기존 `dashboard-separation.test.ts (e)`가 이미 잡고 있었다(`expected 1 to be 2`). 즉 「스위트를 통과한 돌연변이」가 아니라 **「단일 파일만 돌려서 생존으로 보인 돌연변이」**였다. 반대 방향도 같은 자리에서 났다 — 후속 PR에서 `applyDashboard`의 정규화를 걷었더니 전체 스위트에선 **20건**이 죽었는데, 좁게 보면 생존으로 읽혔다(리뷰어가 넘긴 「6곳 중 5곳 생존」 표의 한 줄). / 원인: 속도를 위해 `vitest --run <파일>`로 범위를 좁혀 돌렸다. 계측기는 파일 경계를 모른다 — **한 파일의 사각이 다른 파일에서 덮이는 것은 결함이 아니라 정상**이고, 그 사실은 전체 스위트에서만 보인다. 좁은 실행은 「이 파일이 잡는가」를 답할 뿐인데 보고엔 「스위트가 못 잡는다」로 적힌다. / 해결: **돌연변이 판정은 전체 스위트로 낸다.** 단일 파일 실행은 RED 확인용 빠른 왕복에만 쓰고, **보고에 쓸 사살/생존 수치는 전체 스위트 재실행값**으로 낸다(이번 후속 PR은 6자리 × `npm --prefix frontend test -- --run` 전량으로 쟀다). / 재발방지: 이 레포에서 돌연변이 확인이 구현·리뷰 양쪽의 상시 절차가 된 이상, **「생존」은 전체 스위트 출력 없이 보고하지 않는다.** 살아남은 것처럼 보이면 테스트를 의심하기 전에 ① 주입이 실제로 일어났는지(T-093 계열 — 제자리 치환이 0건인데 통과) ② 범위가 전체였는지, 이 둘을 먼저 본다. / **관련**: 글로벌 「통과는 증거가 아니다」의 **계측 절차판** — 그 원칙이 「이 검사가 무엇을 배제하는가」를 묻는다면 이건 「그 검사를 **어느 범위로** 돌렸는가」를 묻는다 · T-093(주입 실패가 「생존」으로 읽히는 짝 함정
