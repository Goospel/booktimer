# T-195 · 소스 스캔 가드는 「스캔한 것만」 안다 — GREEN은 「규칙이 지켜졌다」가 아니라 「본 파일에서 지켜졌다」다

증상: 웹 제품 UI의 기본 이모지 61줄을 걷어내고 `noEmoji` 가드를 세워 **420건 전부 GREEN**을 받았다. 그런데 `bootRun`으로 실제 화면을 열어 DOM을 훑자 우하단 PWA 설치 칩이 여전히 「📲 홈 화면에 추가」였다. 가드는 그걸 한 번도 본 적이 없어서 조용히 통과시켰다. / 원인: 가드의 스캔 뿌리가 `frontend/src`(Vue 섬)와 `templates`(Thymeleaf) **둘뿐**이었고, 그 칩 문구는 **손으로 쓴 정적 스크립트** `static/pwa-install.js`가 런타임에 만든다. 즉 결함이 사는 파일이 애초에 계측 대상 밖이었다 — 가드가 잡을 수 없는 게 아니라 <b>보지 않은</b> 것이다. 셋째 갈래(정적 스크립트)의 존재를 스캔 설계 때 떠올리지 못한 게 뿌리다. / 해결: 스캔 뿌리에 `static` 루트의 `.js`(`pwa-install.js`·`sw.js`)와 `static/js/`를 더했다. **번들 디렉터리(`static/<섬>/*.js`)는 넣지 않는다** — 소스를 고치면 따라오는 파생물이라 같은 자리를 두 번 신고하게 된다. 가드에 「세 갈래를 모두 훑는다」 단언을 넣어(`.vue`·`.html`·`pwa-install.js` 각 1건 이상) 뿌리가 다시 빠지면 그 테스트가 먼저 깨지게 했다. / 재발방지: ① **소스 스캔 가드를 새로 세우면, 그 가드가 GREEN인 상태에서 실행 화면을 한 번 훑는다** — 범위 밖은 원리상 그때만 드러난다. 훑는 법: `document.body.innerText`를 같은 정규식으로 걸러 0건인지 본다(이번에 실제로 이 한 줄이 잡았다). ② 「가드 GREEN」을 완료의 근거로 삼기 전에 **무엇을 스캔했는지 목록을 소리 내어 확인**한다 — 파일 개수 하한 단언(`length > 30`)은 뿌리가 빠져도 나머지로 채워져 통과한다. ③ 곁다리 함정 하나: 고친 뒤 `fetch('/pwa-install.js')`가 계속 옛 내용을 줘 서버 문제로 오해했는데, 범인은 **서비스 워커 캐시**(`shell-v8`)였고 `cache:'no-store'`로도 안 풀렸다(`caches.delete` + `unregister`가 답). 다만 **운영은 안전하다** — 페이지가 실제로 요청하는 URL은 해시가 박힌 `/pwa-install-<해시>.js`라 내용이 바뀌면 URL이 달라진다. 해시 없는 원본 경로로 자산을 확인하는 것 자체가 검증 방식의 함정이다(T-187 ①의 반대편 짝: 그때는 페이지가 옛 해시를 요청해서, 이번엔 내가 해시 없는 경로를 요청해서 어긋났다). 1회차 신규
