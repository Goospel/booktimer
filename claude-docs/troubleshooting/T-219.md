# T-219 · TDS `Text`의 `style.textAlign`은 DOM에 안 실린다 — 공부 일정 달력의 요일 머리글이 칸 왼쪽에 붙어 날짜 열과 어긋났다

**3회차(T-198·T-216 재발 — T-216 sweep 뒤 새로 쓴 코드가 같은 꼴을 다시 들였다)** / 증상: 실기기(2026-09-02 사용자 스크린샷) 「공부 일정」의 요일 줄 `일 월 화 … 토`가 각 칸의 왼쪽에 붙어, 가운데 선 날짜(1일이 화요일 열)와 반 칸씩 어긋나 보였다 — 요일↔날짜 대응이 눈으로 안 읽힌다. 목 모드 실측(390×844@3x, playwright): 요일 글자 중심 − 날짜 열 중심 = **7열 전부 −19px**, computed `text-align: start`. 월 제목 `2026년 9월`도 같은 꼴 — `minWidth: 120` 상자(글자 90px) 왼쪽에 붙어 화살표 사이 중심에서 **−14.9px**. / 원인: T-216과 같다 — TDS `Text`(`@toss/tds-mobile` 2.5)는 `style`을 그대로 싣지 않고 `{...style, display: displayProp === 'inline' ? 'inline-block' : 'block', textAlign: textAlignProp}`로 **`display`·`textAlign`을 자기 prop 값으로 덮어쓴다**(번들 소스 실측). prop을 안 주면 `undefined`가 덮어 `style={{ textAlign: 'center' }}`가 무성으로 사라진다. #997(09-01)이 T-216(08-29) **이틀 뒤**에 이 꼴을 새로 썼다 — 「리포 전체 sweep」 처방은 기존 자리만 닫고 **새로 쓰는 손**은 못 막는다. / 해결: 정렬을 **`textAlign` prop**으로 준다(`<Text textAlign="center">` — TDS가 그 값을 인라인 `text-align`에 싣는다. `TextProps.textAlign`이 공개 타입). T-216의 「바깥 div가 갖는다」도 유효하되 prop은 한 속성으로 끝나 DOM 노드가 늘지 않는다. 머리글은 격자 아이템이라 블록화되므로 `display`는 줄 것이 없고, 제목은 `minWidth`만 style에 남겼다. 실측: 7열 전부 **Δ=0**, 제목 Δ=0(9월·1월 모두), computed `center`. / 재발방지: **하드픽스(3회차 승격)** — `miniapp/src/text-style-guard.test.ts`가 제품 `.tsx`(테스트·목·픽스처 제외)의 모든 `<Text …>` 여는 태그(중괄호 깊이로 잘라 속성 속 `=>`·`>`에 안 속고, `<TextField>`는 이름 경계로 제외, 주석은 걷는다)를 훑어 `style={{ … }}` 리터럴에 `textAlign` 키가 있으면 파일·태그를 나열하며 실패한다(grep 실측 `<Text` 태그 125개·16파일 — 0개면 빈 가드라는 하한 단언 + 계측기 자체의 양성·음성 대조 3건, T-212 대비). RED에서 `StudyCalendar.tsx` 2곳을 정확히 짚었다. ⚠️ T-216의 「훅 승격 불가 — 부모 상속까지 봐야 죽은 키인지 정해져 정적 판정이 안 된다」는 **판정 대상을 잘못 잡은 말**이었다: 「화면이 틀렸는가」는 부모에 달렸지만 「이 키가 DOM에 실리는가」는 부모와 무관하게 **항상 아니오**라 정적으로 정해진다. 죽은 키를 지우는 것은 언제나 안전하고(부모가 이미 가운데면 지워도 그대로) 산 정렬은 prop으로 옮기면 된다 — 그래서 소스 가드가 성립한다. 보지 않는 것 둘: ① `style={someVar}` 비리터럴(세 회차가 전부 리터럴이었다) ② `display` 키 — 같은 방식으로 덮이지만(`'block'`→`inline-block`) 2026-09-02 실측 **96곳/16파일**이 남아 있어 정리 없이 넣으면 소음이다. 정리하는 날 `DEAD_KEYS`에 더한다. 화면 단언도 하나 더 — `study-calendar.test.tsx`가 머리글 글자를 가장 가까이 감싼 span에 `text-align:center`가 있는지 잰다(RED에서 「`text-align` 없음」으로 정확히 죽었다). / **관련**: T-198·T-216(같은 함정 1·2회차) · T-212(계측기가 대상을 안 잡아도 초록 — 이 가드에 양성 대조를 둔 이유) · T-053·T-176 계열(검증 환경이 관대하면 가짜 green — 정적 렌더는 걸러진 키를 원리상 못 보고, 실기기 스크린샷이 잡았다)
