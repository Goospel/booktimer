# T-277 · 하룻밤 위젯 확인을 다른 세션의 개발 앱 사용이 덮어썼다

## 증상

PR #1366(위젯 자정 항목)은 머지 전에 개발 앱으로 하룻밤 확인(U-115)을 하기로 했다.
2026-10-31 12:53 KST에 PR 머리 Metro로 개발 앱을 열어 위젯을 쓰고(「iOS Bundled」 확인) Metro를 껐다.
11/1 02시, 사용자가 「다른 세션에서 책생글 개발 화면 테스트한다고 백그라운드에 계속 책생글 개발 앱이 켜져있었어」라고 알렸다. 위젯은 「10월 31일」 그대로였다.

## 원인

- 다른 세션(A1 · `feat/a1-app-margin`)이 17:29에 `BookTimer-a1\app`에서 같은 명령(`--port 8082 --scheme booktimer-dev`)으로 Metro를 띄웠다. 17:29~17:44에 개발 앱으로 기기 확인을 했다. 그 브랜치에는 자정 코드(`WIDGET_DAYS_AHEAD`)가 없다.
- 위젯 쓰기는 덧붙이지 않고 저장값을 통째로 바꾼다. expo-widgets `WidgetObject.swift:20-27`이 App Group 키 `__expo_widgets_ReadingWidget_timeline`에 set한 뒤 reload한다. 옛 JS가 홈을 한 번 읽으면(`syncSurfaces`) 자정 항목이 지워지고 「지금」 항목 하나만 남는다.
- 개발 클라이언트는 다시 켤 때 마지막으로 연 주소를 저절로 연다(`EXDevLauncherController.m:88-90 · 257-260`). 두 세션의 주소가 같은 「PC IP:8082」라서 앱은 어느 워크트리의 JS인지 가리지 못한다.
- U-115를 미리보기 게시에서 개발 앱 확인으로 바꿀 때(사용자 결정 D2) 「창 동안 다른 게시 멈춤」은 빠졌다. 그 자리를 대신할 「창 동안 다른 세션은 개발 앱을 쓰지 않는다」는 적지 않았다.

## 해결

- 하룻밤을 PR의 실패로 보지 않고 무효로 판정했다. 근거는 PR 원장 · `plan.md` U-115 줄에 적었다.
- PR 코드 쪽 다른 원인은 코드로 닫았다. 서버 잔디의 앞날 칸은 날짜가 없어 가드를 통과한다(`ContributionGraphBuilder.java:76-83`). 위젯 쓰기 길은 둘뿐이다. 네이티브는 먼 항목을 버리지 않는다.
- 남은 미관측은 「몇 시간 앞 항목을 앱 없이 그리는가」다. 2차 확인과 「지우고 다시 두기」 판별로 본다.

## 재발 방지

- 하룻밤 기기 확인의 CHECK에 통제 조항을 적는다. 쓰기 ~ 확인 동안 다른 세션은 개발 앱을 열지 않는다. 쓰기 직전 8082 주인 명령줄이 내 워크트리인지 확인한다. 쓰기 뒤에는 앱 전환기에서 앞으로 가져오지 않고 밀어 닫는다.
- 덮어쓰기인지 WidgetKit 문제인지 가르는 법이 있다. 홈 화면의 작은 위젯을 지우고 다시 둔다. 다시 둔 위젯이 그린 날짜는 저장된 타임라인이 정한다. 갤러리 미리보기는 첫 항목이라 판정에 못 쓴다.
