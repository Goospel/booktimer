# T-166 · 시트를 닫으면서 다른 화면을 여는 「교체 경로」는 뒤로가기 히스토리 깊이가 한 칸 어긋난다 — `selfPops`는 콜백만 삼키고 깊이는 못 맞춘다

증상: 책방 탭 → 팔로워 시트 → 사람 선택 → 그 사람 책방까지 화면은 전부 정상인데, 거기서 「돌아가기」나 하드웨어 back을 누르면 **내 책방으로 돌아오는 대신 미니앱이 통째로 종료**된다(브라우저에선 앱 이전 페이지로 이탈). 콘솔 에러 0 · 테스트 전건 통과 — 화면 전환만 눈으로 보면 완벽히 정상이라 통과시키기 쉽다. / 원인: `back.ts`의 `close(token)`은 `history.back()`을, `open()`은 `history.pushState()`를 부르는데 **`history.back()`은 비동기**다. 같은 렌더에서 시트를 닫고(effect cleanup → `close`) 다른 서브뷰를 여는(effect → `open`) 교체 경로에서는 pushState가 먼저 실행되고, 그 뒤 큐에 있던 back이 **방금 쌓은 그 엔트리를 도로 소비**한다 → 서브뷰는 열려 있는데 히스토리 인덱스는 앱 루트다. `selfPops` 카운터는 그때 도착하는 popstate **콜백**을 삼켜 "다음 화면이 저 혼자 닫히는 것"만 막는다 — 깊이 어긋남 자체는 방어 대상이 아니었다(주석의 설계 의도가 콜백까지만이다). 실측: 시트 열림 `history.length=3 · state={"booktimer":"subview"}` → 사람 선택 후 `length=3 · state=null`(서브뷰가 열렸는데 state가 null이면 어긋난 것). / 해결: **엔트리 물려주기(handoff) + `close()`의 back을 마이크로태스크로 지연**(`back.ts`). `close()`는 즉시 `nav.back()`을 쏘지 않고 `handoff++` 후 `queueMicrotask`로 판정을 미룬다 — React가 한 커밋에서 **cleanup을 먼저·setup을 나중에 동기 실행**하므로, 뒤따르는 `open()`이 `handoff > 0`이면 그 반납 예정 엔트리를 **물려받아 push도 back도 하지 않는다**(하나 나가고 하나 들어오니 오갈 것이 없다). 물려받을 `open()`이 안 오면 마이크로태스크가 예정대로 `selfPops++` + `nav.back()`으로 반납한다. 교체 연산을 `createBackStack`에 새로 다는 안은 기각했다 — `useBackClose(active, onClose)` 시그니처로는 "교체"를 표현할 길이 없어 호출부까지 번진다. 실측(목 모드): 교체 후 `history.state`가 `null` → `{"booktimer":"subview"}`로 바뀌고, 「돌아가기」가 앱을 나가는 대신 내 책방으로 복귀한다. / 재발방지: ① **"닫으면서 연다"는 라우팅 교체 경로는 화면이 아니라 히스토리 깊이로 검증한다** — 목 모드에서 단계마다 `history.length`·`history.state`를 찍어, 서브뷰가 열렸는데 `state`가 subview가 아니면 어긋난 것이다. ② 정적 렌더 하니스는 effect를 안 돌려 이 클래스를 **원리상 못 잡는다**(T-149 계열) — 실 브라우저가 유일한 계측기다. ③ 뒤로가기 스택처럼 **브라우저 API의 비동기성이 섞인 자원**은 "콜백이 옳게 불렸는가"와 "자원 깊이가 맞는가"가 별개 단언이다 — 전자만 지키는 가드를 후자의 보증으로 읽지 않는다. ④ 이 클래스의 회귀 테스트는 **`push`/`back` 호출 수**로 쓴다(`back.test.ts`의 주입 `BackNav`) — "화면이 맞게 떴는가"로는 영영 안 잡힌다. 지연이 생겼으니 단언 전에 `await Promise.resolve()`로 마이크로태스크를 흘린다. 1회차 신규 — 책방 개편(소셜 탭 → 책방 탭) 목 모드 검증 중 발견. **이번 개편이 만든 회귀는 아니다**: 스토리 뷰어 → 「책방 보기」 → 「돌아가기」가 같은 교체 경로이고 그 코드는 무변경인데 동일하게 재현됐다(`git diff`로 `back.ts`·`Story.tsx` 무변경 확인). 다만 개편 전에는 남의 책방으로 가는 길에 시트를 안 거치는 경로(인라인 검색 결과·인라인 팔로우 목록)가 있어 주 경로는 멀쩡했고, 개편 후에는 **모든 진입이 시트 경유**라 결함이 주 경로로 올라왔다
