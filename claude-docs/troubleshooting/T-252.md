# T-252 · 토스 심사가 「미니앱 최초 접속 시간 20초 초과」로 반려했다 — 공개 체크리스트에 없는 기준이고, 이번 번들에서 첫 화면에 새로 생긴 동작은 「게스트 홈이 열리자마자 나가는 타임아웃 없는 요청」 하나였다

**1회차** / 증상: 번들 `20260917-152`(#1155 로그인 선택 화면 제거 + #1156 게스트 홈 책 뉴스)가 17:55 검수 요청 → 18:08 반려, 사유 「미니앱 최초 접속 시간이 20초를 초과하여 로딩 성능 개선이 필요해요」. 이 앱 첫 사례이고, [비게임 체크리스트](https://developers-apps-in-toss.toss.im/checklist/app-nongame)의 성능 항목은 「인터랙션 반응 2초」뿐이며 검수 공지(52485·52775)에도 20초 기준이 없다. 사용자 실기기에서는 정상으로 떴다. / 원인(**확정 아님** — 심사 환경 재현 불가): diff부터 떠서 후보를 지웠다(T-185 순서). ① 무게: 직전 커밋 빌드 JS 1,391.77KB → 1,392.30KB(+0.5KB) — 배제 ② 서버: 심사 시간대(08:55~09:08 UTC) `Deploy to EC2` 실행 없음, 운영 `/api/public/news`·`/actuator/health` 응답 0.5초 이내 — 배제 ③ 첫 화면 동작: 그전 게스트 홈은 **서버를 한 번도 안 불렀는데**, #1156이 `GuestShell` 마운트 effect에서 `fetchPublicNews()`를 곧바로 불렀고 공용 `request()`엔 **타임아웃이 없다**(`fetch` 기본값 무한). 화면 표시는 그 요청을 기다리지 않지만, 막힌·느린 네트워크에서 요청이 끝나지 않으면 「로드가 끝난 시점」을 재는 계측이 늘어질 수 있다. 남는 변수는 이것 하나였다. / 해결: #1160 — `RequestOptions.timeoutMs`(AbortController, 초과 시 `NetworkError`)를 더해 공개 뉴스만 5초 상한, 요청을 `whenPageLoaded(document, window, fn)`로 `load` 이벤트 뒤로 미룸(정리 함수로 언마운트 뒤 요청 차단). 못 받으면 옛 잠금 화면 그대로. 돌연변이 5종 사살. 새 문구가 없어 `deploy.sh`는 `--expect` 없이(번들에 `timeoutMs:5e3` 실린 것을 문자열로 확인) `20260917-153` 업로드 → 재제출 → **승인·출시(21:04)**. / 재발방지: **미니앱 첫 화면(게스트 홈·로그인 홈 진입)에 네트워크 요청을 새로 넣을 땐 타임아웃을 걸고 페이지 로드 뒤로 미룬다** — `request(path, { timeoutMs })` + `whenPageLoaded`. 로그인 홈의 대시보드 요청 등 기존 첫 화면 요청은 이번에 손대지 않았다(그 경로로 같은 사유가 또 나면 여기부터 본다). 같은 사유로 재반려되면 요청이 원인이 아니었다는 뜻이니 채널톡으로 측정 조건(기기·네트워크·기준 시점)을 묻고 번들 무게(1.39MB)를 검토한다. ⚠️ 출시노트에 「없앰습니다」 오타가 남았다 — 검수 중엔 `bundle_set_release_note`가 거부되고 `review_cancel`하면 그 배포는 재요청 불가라, 제출 전 노트 본문을 한 번 더 읽는다. / **관련**: T-185(반려 사유를 직전 통과분 diff에 먼저 대 본다) · T-220(사유가 공개 필수 항목인지 먼저 본다 — 이번엔 아니었다) · T-176(성능 클래스는 실기기가 유일한 게이트 — 이번엔 실기기도 통과해 심사 환경만 늘어졌다)
