# T-189 · 인라인 스타일 값을 선택자 키로 쓰는 수법이 카드에선 과잉 적용된다 — 색은 컴포넌트를 가리키지 않는다

증상: 미니앱 카드에 연필 테두리를 얹으려고 `[style*='#FCFAF5'] { border-image: … }`로 카드지 색을 선택자 키로 썼더니, **기록 화면의 날짜 줄 하나하나에까지** 테두리가 둘러쳐지고 오른쪽 시간 텍스트가 선에 잘렸다. / 원인: 이 수법 자체는 이 레포의 검증된 기법이다 — TDS Button은 클래스가 해시라 잡을 손잡이가 없어 인라인 `--button-background-color` 값을 키로 쓴다. **그러나 그때 통한 이유는 그 색이 버튼에만 쓰이기 때문**이었다. 카드지 색은 카드·목록 행·배지가 **전부 공유**하므로 같은 키가 전혀 다른 것들을 함께 집는다. 즉 「인라인 값 = 컴포넌트 정체성」이 성립하는 색과 아닌 색이 있다. / 해결: 광범위 규칙을 걷고 **쓰는 자리에서 명시적으로** 얹었다 — 공통 카드는 `ui.tsx`의 `sectionStyle`, 그 밖은 각 화면에서 `borderImage: PENCIL_FRAME`을 직접 준다. / 재발방지: ① 인라인 값을 선택자 키로 쓰기 전에 **"이 값이 이 컴포넌트에만 쓰이는가"를 먼저 확인한다** — 아니면 과잉 적용이고, 그 증상은 "의도한 곳은 되는데 엉뚱한 곳도 같이 된다"라 코드만 봐선 안 보인다. ② 부수 효과가 **화면을 훑어야만 보이므로**, 이런 일괄 규칙을 넣은 뒤엔 반드시 **전 화면을 눈으로 지나간다**(이번에도 홈·서재·책방은 멀쩡했고 기록에서만 드러났다). ③ ⚠️ **속성 선택자는 브라우저가 정규화한 문자열을 본다** — React가 인라인 style을 CSSOM에 넣으면 색이 `rgb(252, 250, 245)`로 다시 쓰이므로 hex 키만 적으면 조용히 안 걸린다(TDS Button 선택자가 콜론 뒤 공백을 두 벌 적는 것과 같은 뿌리). 1회차 신규
