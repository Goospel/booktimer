# T-156 · TDS `Wheel`은 스스로 높이를 만들지 않는다 — 시트 밖 인라인으로 쓰면 부모에 명시 높이가 없을 때 항목이 한 줄에 겹친다

증상: 목표 화면을 프리셋 칩에서 `Wheel` 2열(시간/분)로 바꿨더니 드럼이 아니라 모든 항목이 한 줄에 포개진 글자 뭉치로 렌더됐다. aria-checked·onChange·저장 경로는 전부 정상이라(로직 테스트 319건 green) 코드 결함처럼 안 보인다. / 원인: 번들 실측 — `Wheel` 루트 스타일이 `height:"100%"`(회전판 16%·안개 42%도 전부 %)라 **부모 높이에 전적으로 의존**한다. 원래 `WheelDateSheet` 같은 시트 컴포넌트가 높이를 제공하는 구조라, 높이 없는 flex div에 넣으면 100%×0=0이 되고 항목은 absolute라 겹쳐 쌓인다. 정적 렌더 하니스(jsdom 없음)는 레이아웃을 계산하지 않아 **원리상 못 잡고**, 실브라우저에서만 보인다. / 해결: 휠들을 감싸는 컨테이너에 명시 높이(`height: 180`) 부여 — 칸 하나 높이가 컨테이너의 16%라 180px→약 29px. / 재발방지: Goal.tsx 컨테이너 주석에 실측 근거(루트 100%·칸 16%) 기재 + 렌더 단언 1건(`height:180px` 존재, 돌연변이 실측으로 계측 유효성 확인). TDS 복합 컴포넌트를 **원래 감싸는 시트/트리거 밖에서 단독 사용할 땐 그 래퍼가 제공하던 레이아웃 전제(높이·perspective 등)를 먼저 번들에서 실측**할 것. 1회차 신규 — "헤드리스로 원리상 못 잡는 시각 결함"이라는 결이 T-053·T-054(로드순서)·T-154(패널 가시성)와 닿지만 이쪽은 CSS % 상속 메커니즘이라 별개. 목표 휠 피커 전환(#739 브랜치) 중 발생
