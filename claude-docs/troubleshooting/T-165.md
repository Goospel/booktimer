# T-165 · 선택 state는 바뀌는데 스크롤이 안 따라간다 — 명령형 DOM 상태(`scrollLeft`)를 특정 핸들러 안에서만 갱신하면, 그 state를 바꾸는 새 경로가 생기는 순간 화면이 조용히 갈린다

증상: 서재 「펼쳐보기」 격자에서 책을 고르면 캐러셀 **아래 제목·메타는 그 책으로 바뀌는데 표지 트랙은 옛 자리 그대로**였다. 콘솔 에러 0, 테스트 전건 통과 — 한 화면의 두 표시가 서로 다른 책을 가리키는 상태라 "무엇이 고장났는지"가 코드에 안 드러난다. / 원인: 한 컴포넌트 안에 **선언형(state → 렌더)과 명령형(`scrollLeft` 대입)이 섞여** 있었다. 제목·메타는 `selectedId`를 읽어 그리므로 **어느 경로로 바뀌든** 따라오지만, 트랙 위치는 **마운트 effect와 표지 `onClick` 두 핸들러 안에서만** 갱신됐다. 나중에 붙은 격자의 `onPick`은 그 둘 중 어느 쪽도 아니라 state만 바꾸고 DOM은 남았다 — 선택을 바꾸는 경로가 늘어날 때마다 새 경로 쪽이 무성으로 갈린다. / 해결: 스크롤 갱신을 핸들러가 아니라 **state에 종속**시킨다(`useEffect(…, [selectedId])`가 트랙을 맞춘다). 단 스냅 캐러셀이라 무조건 재스크롤하면 **손가락으로 민 직후에도 스크롤이 걸려 스냅이 트랙을 손에서 빼앗으므로**(T-159 ③과 같은 사고), 순수 함수 `recenterIndex`가 **현재 가운데 칸 == 목표 칸이면 `null`**을 돌려 no-op으로 만든다. / 재발방지: ① **명령형 DOM 상태(`scrollLeft`·`focus`·`scrollIntoView`·미디어 재생위치)를 특정 핸들러 안에서만 갱신하지 않는다** — "이 값이 바뀌면 DOM은 어떠해야 하는가"로 state에 종속시킨다. 핸들러에 심으면 호출자가 늘 때마다 빠뜨리고, 빠뜨린 쪽은 **에러 없이** 갈린다. ② 그 대가로 되돌아오는 위험은 **사용자 조작이 만든 DOM 상태를 다시 덮는 것**이므로 "이미 그 상태면 아무것도 안 한다" 가드를 함께 둔다 — 그 판단을 **순수 함수로 꺼내면 jsdom 없는 하니스에서도 계측된다**(T-149 회피와 같은 손질). ③ 화면에 같은 값을 가리키는 표시가 둘 이상이면(제목 줄 · 표지 위치) **한쪽만 state 종속이 아닌지** 의심한다 — 이 결함의 서명은 "둘이 서로 다른 것을 가리킴"이다. 1회차 신규 — 같은 캐러셀에서 나온 T-159·T-160과 컴포넌트만 같고 메커니즘은 별개다(저 둘은 웹뷰 엔진 차이, 이쪽은 React state ↔ 명령형 DOM 갱신 경로의 갈림). 엔진 문제가 아니라 배선 문제라 **목 모드 브라우저로 재현·검증이 모두 가능**했다(`scrollLeft` 0 → 100 실측). 서재 「펼쳐보기」 사용자 제보로 발견
