# T-164 · `Story.of`는 공개 책만 받는데 `Book.register`는 PRIVATE 기본이라, 스토리 픽스처가 도메인 규칙에 막혀 테스트가 시작도 못 한다

증상: 탈퇴 통합 테스트에서 "자식 데이터를 가진 계정"을 만들려고 세션·책·팔로우·스토리·차단·신고 픽스처를 쌓는데, 스토리 생성 지점에서 예외가 나 테스트가 **본론(삭제) 전에** 실패했다. 삭제 로직 버그로 오인하기 쉽다 — 실패 지점이 given 단계인지 when 단계인지 스택만 보고는 즉시 안 갈린다. / 원인: 도메인 규칙이 둘 맞물린다 — ① `Book.register`는 **visibility PRIVATE이 기본**이다(공개는 opt-in 불변식) ② `Story.of`는 **공개 책에만** 스토리를 허용한다(비공개 책을 스토리로 올리면 공개 의사에 반한다). 둘 다 옳은 규칙인데, 픽스처를 "책 만들고 스토리 올린다" 순서로 쓰면 그 사이에 `makePublic()`이 빠진다. / 해결: 픽스처에서 책을 만든 뒤 `makePublic()`을 호출하고 스토리를 만든다. / 재발방지: ① **픽스처가 도메인 불변식에 걸리면 그건 테스트 버그가 아니라 "실제 사용자도 그 순서로는 못 한다"는 신호**다 — 우회(리플렉션·직접 setter)하지 말고 실제 사용 순서를 따른다. ② opt-in 불변식(PRIVATE 기본·PUBLIC 명시)을 가진 엔티티를 부모로 쓰는 픽스처는 **공개 전환 한 줄이 필요한지 먼저 확인**한다. 1회차 신규 — 경미(즉시 드러나 사고로 이어지지 않는다). 미니앱 회원 탈퇴 통합 테스트 작성 중 발생
