# T-223 · `open(path, "w")`는 「여는 순간」 truncate한다 — 뒤이은 인코딩 예외로 쓰기가 죽어도 원본은 이미 사라진 뒤였다. 1.36MB changelog가 3KB로 잘렸다**) / **1회차

증상: 웹 타이포 PR에서 `changelog.md` 맨 아래에 한 줄을 붙이려 파이썬으로 「읽고 → 합쳐서 → 다시 쓰기」를 했다. 스크립트는 `UnicodeEncodeError: surrogates not allowed`로 죽었고, **에러를 봤으니 아무 일도 안 일어났다고 넘겼다.** 실제로는 파일이 **1,362,355 → 3,327바이트**(873행 → 2행)로 잘려 있었다. 커밋 직전 `git diff --stat`이 `claude-docs/changelog.md | 873 +---------------`(895 deletions)를 띄워 발견했다 — **한 줄 추가가 873줄 삭제로 보이는 것**이 유일한 신호였다. / 원인: 두 가지가 겹쳤다. ① **`open(p, "w")`는 파일을 여는 시점에 즉시 길이 0으로 자른다** — 쓰기 성공 여부와 무관하다. 그래서 `open(p,"w").write(txt + line)`에서 `write()`가 예외를 던져도 원본은 되돌아오지 않는다. 「예외 = 무변경」이라는 직관이 틀린 자리다(무성 실패가 아니라 **에러가 났는데 파괴가 남는** 유형이라 더 헷갈린다). ② 예외 자체는 내 실수였다 — 파이썬 소스에 이모지를 `"📍"`처럼 **서로게이트 쌍 이스케이프**로 적으면 파이썬은 이를 결합하지 않고 lone surrogate 두 개로 들고 있다가 UTF-8 인코딩에서 죽는다(📍는 `"\U0001F4CD"`로 써야 한다). / 해결: 추적 파일이라 `git checkout -- claude-docs/changelog.md`로 즉시 복구(1,362,355바이트·873행 확인)한 뒤, 붙일 한 줄은 **별도 UTF-8 파일에 리터럴로** 써 두고 `open(p, "ab")`로 이어붙였다. 최종 `git diff --numstat`이 `1 0`인 것으로 검증. / 재발방지: ① **덧붙이기는 반드시 `"a"`/`"ab"`** — 읽고-합쳐-다시쓰기 패턴을 큰 문서에 쓰지 않는다(append는 원본을 열지도 않으므로 이 사고가 구조적으로 불가능하다). ② 파이썬으로 문서를 다시 써야만 한다면 **쓰기 전 원본 바이트 수를 재고, 쓴 뒤 다시 재서 대조**한다 — 줄어들었으면 그 자리에서 크래시시킨다. ③ 이모지·비ASCII는 소스에 이스케이프로 박지 말고 **별도 UTF-8 파일에서 읽어 온다**(hookify 룰이 경고하는 「제자리 치환」과 같은 뿌리 — 눈에 안 보이는 바이트를 손으로 짜지 않는다). ④ 문서를 만진 커밋 직전엔 **`git diff --numstat`으로 파일당 증감 줄 수**를 본다(`git status`의 `M` 하나로는 1줄 추가와 873줄 삭제가 구분되지 않는다). 훅 승격은 1회차라 보류 — 다만 `open\([^)]*['\"]w['\"]` 는 정규식으로 잡히는 부류라 2회차면 hookify block 룰이 바로 가능하다. / **관련**: T-093·T-103·T-172·T-209(스크립트가 파일을 통째로 다시 써서 조용히 깨지는 같은 군 — 그쪽은 EOL 뒤집힘, 이쪽은 내용 소실) · T-221(같은 PR에서 만난, 파일 경유 작업의 다른 함정
