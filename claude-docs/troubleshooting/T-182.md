# T-182 · 오버레이(코치마크)는 정적 렌더 하니스가 원리상 못 보는 두 자리에서 깨진다 — ① 뜰 차례를 마운트 1회로 판정하면 나중에 온 차례를 놓치고 ② 늦게 로드된 콘텐츠가 대상을 화면 밖으로 밀어내면 딤만 깔린 검은 화면이 된다

증상: 코치마크 5개(탭바 투어 3걸음 + 인라인 2개)를 붙이고 단위 705건·`tsc` 전부 GREEN인데, 목 모드 실 브라우저에서 둘이 드러났다. ① 투어 마지막 걸음을 닫아도 **그 화면(홈)에 서 있는 동안은 여백 안내가 안 뜬다**(탭을 나갔다 오거나 앱을 다시 켜야 뜬다) ② 서재를 열면 **화면 전체가 어두워지기만 하고 말풍선도 밝은 대상도 없다** — 스크롤을 내리면 저 아래에 둘이 있다. / 원인: ①은 「뜰 차례인가」를 `useState(() => !seen(name) && seen(after))`로 **마운트 1회만** 계산한 것. 투어가 끝나 `after` 키가 생겨도 이미 마운트된 화면은 그 초기값을 그대로 들고 있어, 부모가 리렌더돼도 값이 안 바뀐다(상태의 초기화 함수는 다시 안 돈다). ②는 `scrollIntoView`를 안 건 것 + **건 뒤에도 늦게 도착한 콘텐츠에 밀린 것**이다 — 서재의 인라인 여백 박스가 fetch 후 글 카드를 채우며 문서가 길어져, 스크롤로 데려온 「책 추가하기」가 다시 아래로 내려갔다. 두 자리 모두 하니스(`renderToStaticMarkup`, jsdom 없음)로는 **원리상 안 보인다**: effect가 안 돌고 레이아웃·스크롤이 없어 좌표가 존재하지 않는다. / 해결: ① 상태로 드는 것은 **「닫았는가」 하나**로 줄이고 **뜰 차례는 매 렌더 파생값**으로 계산한다(`const open = !closed && (after === undefined || coachmarkSeen(after))`) — 부모 리렌더에 곧바로 따라온다. ② `scrollIntoView({ block: 'center' })`를 걸고, **안내가 떠 있는 동안만** `ResizeObserver(document.body)`로 재스크롤한다(닫히면 `disconnect`). / 재발방지: ① **`localStorage`·전역 상태를 「지금 보여줄까」의 근거로 쓸 때, 그 값이 이 컴포넌트 밖에서 바뀔 수 있으면 마운트 1회 판정은 버그다** — 초기화 함수(`useState(() => …)`)는 정적 렌더 계측을 위한 관례일 뿐이고, **계측 편의가 판정 시점을 잘못 고정하게 만든 것**이 이번 실수의 구조다. 상태는 그 컴포넌트가 스스로 바꾸는 것(닫힘)만 들고, 밖에서 오는 조건은 파생으로 둔다. ② **오버레이가 가리키는 대상이 화면 안에 있다고 가정하지 않는다** — 딤은 뷰포트를 덮으므로 대상이 스크롤 밖이면 「전체가 어두워졌을 뿐」이 되고, 사용자에게는 앱이 멈춘 것으로 보인다. 데려오는 것(`scrollIntoView`)에 더해 **늦게 오는 콘텐츠에 밀리는 것까지** 막아야 한다(비동기 박스·이미지·피드가 있는 화면이면 반드시). ③ **목 픽스처가 「비어 있는 초기 상태」면 이 클래스는 안 보인다** — 신규 사용자의 서재는 책 0권이라 버튼이 화면 위쪽에 오고, 책이 쌓인 기존 사용자에게만 터진다. 새 안내는 **기존 사용자도 1회 보는** 설계라(키 부재 = 노출) 픽스처를 채운 상태로도 반드시 확인한다. ④ 진단: 「딤만 보이고 말풍선이 없다」·「어두워졌는데 누를 것이 없다」가 나오면 **CSS·층을 파기 전에 대상의 `getBoundingClientRect()`가 뷰포트 안인지** 먼저 잰다. **5회차 = T-053·T-054·T-176·T-177 재발군**(검증 환경이 실환경보다 관대하면 그 클래스는 가짜 green으로 통과한다 — 이번 축은 **정적 렌더 vs 실 브라우저**의 effect·레이아웃. 규칙은 이미 있어서 실 브라우저 게이트가 둘 다 잡아냈다 = 승격이 작동한 사례) — 트래커 갱신
