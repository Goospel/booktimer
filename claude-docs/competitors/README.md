## 계획에서 쓰는 법

사용자에게 보이는 변경(화면·기능·스토어 문구·온보딩·수익화)의 계획에는 세 줄을 넣는다. 행 id는 각 문서 대조표의 것이다.

```
경쟁사 대조:
① 같은 게 있나 — 북트랙 C41(바코드 등록): 같음, 이미 출시.
② 차별 — 키우지도 흐리지도 않는 동등 기능. 투자 수준은 이 계획에서 정한다(권고: booktrack.md §4-1 「충분히 좋게」에서 멈춤).
③ 따라가는 근거 — 해당 없음(책생글 v1 범위의 「건지기」 단계로 이미 합의된 기능).
```

①의 판정은 대조표의 말(같음·비슷·다른 방식·북트랙만·우리만·우리만?)을 그대로 쓰고, 경쟁사 쪽을 모르면 「모름」이라고 쓴다.

해당 없는 작업은 `경쟁사 대조: 해당 없음` 한 줄이다. 인프라·훅·문서, 그리고 사용자에게 보이는 동작이 바뀌지 않는 리팩터·버그 수정이 여기 든다. 빈칸으로 두지 않는다.

## 갱신 규칙

- **새 소식을 알게 되면 그 경쟁사 문서부터 고친다**: 사용자가 보낸 링크·캡처, 스토어 업데이트, 새 기능 같은 것이다. 행을 고치거나 덧붙이고, 맨 위 「마지막 확인」 날짜와 맨 아래 갱신 이력을 바꾼다. 이 표의 「마지막 확인」도 함께 바꾼다.
- **행 id는 바꾸지 않는다.** 계획·PR이 id로 인용한다. 새 행은 끝 번호 다음부터 단다. 없어진 기능은 행을 지우지 말고 판정을 고친다.
- **근거 등급을 단다**: (화면) 실기기·에뮬레이터 캡처 / (합성) 스토어용 합성 이미지 / (문구) 소개 글뿐 / (모름). 「경쟁사에 없다」와 「경쟁사 쪽은 모른다」를 섞지 않는다. 섞이면 ②에서 근거 없이 「우리만」으로 세게 된다.
- **경쟁사의 스크린샷·문구 원본은 레포에 커밋하지 않는다.** 요약과 출처 URL만 둔다(저작권).
- **클라우드 세션에서 다시 볼 때**: github.io와 App Store·Google Play는 프록시가 막는다. 소개 사이트 원본은 `raw.githubusercontent.com` 경로로 받는다(각 문서 「출처」). 스토어 메타데이터(평점·다운로드·버전 이력)는 사용자 캡처가 유일한 경로다.
- **읽기 화면(아티팩트)**: 사용자는 md 원문을 읽기 불편해해서 경쟁사 문서를 한 페이지로 그린 비공개 아티팩트가 있다 — <https://claude.ai/artifact/C9jRd4DbiGP7NktVZbtTtH>. 원본은 이 폴더의 md이고, 화면은 사본이다. md를 고쳤으면 `node scripts/competitors-reader/build.mjs <출력 경로>`로 다시 만들어 **같은 URL로** 다시 게시한다(Artifact `url`). 「한눈에」 탭의 단계 그림·표·앱 카드는 `scripts/competitors-reader/template.html`에 손으로 쓴 요약이라, 판정이 바뀌거나 경쟁사가 늘면 그것도 함께 고친다. 앱 순서는 규모(App Store + Google Play 평가 수, 스토어 없는 곳은 인스타 팔로워로 맨 뒤) 순이고, 템플릿의 순위 · 카드 「평가 N」 숫자도 손으로 쓴 값이라 재확인 때 함께 고친다. 스크린샷 · 앱 아이콘은 레포에 두지 않고(공개 레포에 남의 앱 화면을 싣지 않는다) 아티팩트의 게시 파일 `shots/`(App Store 조회 API `screenshotUrls` · `artworkUrl100`, 웹 전용 두 곳은 휴대폰 폭 캡처)로만 둔다 — 다시 게시할 때 `files`를 빼면 그대로 남는다.
- **새 경쟁사**는 사용자가 지정할 때만 추가하고, [booktrack.md](booktrack.md)와 같은 틀로 쓴다. 전수 대조표가 필요 없는 경쟁사는 [serotiny.md](serotiny.md)처럼 「그 앱이 나은 점 / 북타이머가 나은 점」 두 표를 대조표 대신 써도 된다(행 id는 문서마다 접두어를 따로 단다 — SR · SQ · TS · TP · TX · PG · CI · BL).
