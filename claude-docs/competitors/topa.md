## 1. 한눈에

- **무엇**: (주)제타스코프가 운영하는 **AI 대화형 책 추천 웹 서비스**. 지금 기분·상황·읽고 싶은 책을 자연어로 적으면 AI가 되물으며 대화하고, 추천 이유·요약·독자 리뷰를 붙인 책 5권쯤과 후속 질문 5개를 준다. 구매는 교보문고로 넘긴다. 앱은 없다(스토어 검색 0건).
- **축**: *무엇을 읽을지 고르기*. 독서 기록·타이머·목표·습관 기능은 **없다**(번들의 한글 문자열 1,284개에서 「타이머·목표·연속·알림·완독·별점·메모·감상」 0건).
- **위치**: 가천대 학생 창업(2025 법인), 경기도 대학생 창업지원 S등급(3,000만 원). 같은 엔진을 공공도서관 키오스크와 교보문고 PoC에 B2B로 공급한다(기사). 2026-09엔 「2주 안에 유저 천 명」 챌린지 릴스를 하다 유입이 저조해 멈췄다고 스스로 밝혔다(광고).
- **우리와 맞붙는 곳**: **거의 없다.** 우리는 「고른 책을 읽고 쓰기」, topa는 「읽을 책 고르기」다. 겹치는 것은 *책 추천*과 *서점 구매 연결* 두 귀퉁이다. 최근 광고(2026-10-23)는 「올해 책 0권 탈출」로 *독서를 포기한 사람*을 부르는데, 이는 웹 북타이머의 원래 입구(입문자의 작은 습관)와 같은 사람들이다.

## 5. 설계 지침 — 경쟁사 대조의 ②·③을 쓸 때

> **권고**다. 채택은 각 작업의 계획에서 사용자가 정한다.

1. **책생글 v1엔 영향 없음**: v1은 추천을 하지 않는다. topa를 이유로 범위를 넓히지 않는다.
2. **「AI 사서」 백로그를 다시 열 때의 기준선**: 대화로 되묻기 · 책마다 추천 이유 · 리뷰 모음 · 후속 질문. 우리가 낼 수 있는 차이는 「내 기록(여백·완독)에서 출발한다」다(TP12) — 같은 것을 입력창 하나로 따라가지 않는다.
3. **공개 글 페이지·SEO를 설계할 때 참고**: 공개 동의 · 민감 맥락 걸러내기 · 공개용으로 문장 다듬기 · 슬러그와 sitemap은 우리 「SEO 보류」를 다시 볼 때 그대로 점검표가 된다. → 2026-10-30: 공개 글 페이지는 Phase 4b가 아니라 첫 출시 설계(승인 · 미출시 — E2(2026-12-01)부터 서버에서 열림)의 웹 블로그 글 · 문장 주소(로그인 없이 읽기 — D14)로 앞당겨졌다. 사이트맵 · SEO 작업은 그 설계도 비목표다(외부 유입이 생길 때 — 설계 §4).
4. **「책 0권 탈출」 층**: topa가 광고로 부르는 「독서를 포기한 사람」은 웹 북타이머의 원래 입구(타이머 = 입문자의 작은 습관)다. 우리 thesis는 2026-10-17에 「읽은 것을 글로 남기는 20~30대」로 옮겼으니 이 층을 쫓지 않는다 — 다만 타이머 입구를 문구로 다시 쓸 때 겹치는 말을 피한다.

## 6. 감시 신호

- **독서 기록·습관 기능이 생긴다**(담은 책에 읽음 상태·진도가 붙는다) → TP11. 추천 → 기록으로 내려오면 우리 입구와 맞붙는다.
- **앱이 나온다** → TP15. **교보 PoC가 교보 앱 안 기능으로 나온다** → 규모가 바뀐다.
