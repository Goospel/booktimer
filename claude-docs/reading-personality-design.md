# 독서 성향 분석 ("책장 기반 MBTI") — 설계 메모 (구현 전 합의용)

> **상태**: 설계 초안 (⏳ 2026-06-05, 방향 합의). **코드 없음.** 이 문서로 "AI에 뭘 시키나 / 비용 / 프라이버시 경계"를 먼저 못 박은 뒤 TDD로 들어간다.
> **왜 설계 먼저**: 결과가 **타인에게 노출**되고(②사용자 상호작용) **외부 LLM 호출 비용**이 붙으므로, 노출 경계·캐시 정책을 코드에 굳히기 전에 합의가 필요하다.
>
> 관련: [plan.md](../plan.md) §독서 성향 분석 · [sns-design.md](sns-design.md) §3.5(가시성 경계) · [learning-notes.md](learning-notes.md) **N-037**(저장 대상=기존 데이터 해석).

## 0. 한눈에 — 이 메모가 정한 방향

| 항목 | 결정 | 확정? | 근거 |
|---|---|---|---|
| 출력 형태 | **자유 서술문**("이 사람은 ~한 독자다", MBTI 설명문체) | ✅ | 사용자 정의 — 고정 16유형 아님 |
| AI 사용 여부 | **쓴다 (서술 생성에)** | ✅ | 책→성향은 퍼지한 해석, 자유 자연어 = LLM 강점 |
| **AI의 역할 경계** | **해석·서술만**. 사실 집계(숫자 세기)는 코드가 | ✅ | 환각·비용↓, 품질↑ |
| 입력 | **압축된 "독서 프로필"**(코드가 책장에서 집계) | ✅ | raw 통째로 던지지 않음 |
| 출력 2겹 | 설명문 **+ 짧은 태그/점수**(기계 비교용) | 🟡 | ②매칭하려면 비교 핸들 필요 |
| 모델 | 소형(Haiku/4o-mini/Flash 급) | 🟡 | 호출당 1원 미만 |
| 갱신 | **결과 저장·캐시**, 책장 의미변화 or "다시 분석"시만 재생성 | ✅ | 비용↓ + 결과 일관성(공유 캡처) |
| 프라이버시 | 분석은 본인 책만 / 공개 결과는 PUBLIC 책 기반 | 🟡 | sns §3.5와 동일 — 비공개 간접 누출 차단 |
| Flyway | 결과 저장 테이블 필요 시 신규(번호는 머지 직전) | 🟡 | 파생 캐시 vs 매번 계산 결정에 달림 |

> ✅ = 합의됨. 🟡 = 제안(착수 전 확정). **§7 열린 질문**에 미결 정리.

## 1. 사용자 정의 컨셉

> 사용자가 직접 정의(2026-06-05). 이후 변경 시 이 절 갱신.

- 누군가가 **타인의 책장을 보고** "이 사람은 이런 성향의 독자다~" 하는 **설명문**을 얻는다. MBTI 설명문처럼 **읽는 재미**가 핵심.
- 단, MBTI식 **고정 유형(16종)으로 정형화하지는 않는다** — 책으로 사람 성향을 깎기엔 퍼지하므로, **자유 서술**이 더 맞다고 판단.
- 그래서 **AI(LLM)로 서술문을 생성**한다.

---

## 2. 핵심 설계 결정 — "AI를 쓰냐"가 아니라 "AI한테 뭘 시키냐"

성향 도출을 두 역할로 쪼갠다. 이 분리가 비용·환각·품질을 동시에 잡는다.

| 단계 | 담당 | 내용 | 성격 |
|---|---|---|---|
| ① **사실 집계** | **코드/DB** | 장르 분포·완독률·자주 읽은 저자·책별 누적 시간·다독/정독 경향 등 | 결정적·$0·테스트 가능 |
| ② **해석 + 서술** | **LLM** | ①의 사실을 받아 자연어 성향 설명문 생성 | 퍼지 종합·자연어 = AI 강점 |

```
책장(book + reading_session)
   → [코드가 "독서 프로필"(사실)로 압축]
   → [LLM이 그 사실을 해석해 MBTI식 설명문 생성]
   → 결과 저장(캐시)
```

> 요지: **고정 축 판정을 건너뛰는 것이지 AI를 빼는 게 아니다.** 반대로, **AI한테 숫자를 세게 하지 않는다**(비싸고 부정확). 코드가 센 사실을 AI가 해석·서술한다.

---

## 3. 입력 — "독서 프로필"(코드가 집계하는 사실)

LLM에 raw 행을 통째로 던지지 않는다. 토큰↓·환각↓·신호 선명. 후보 사실(착수 전 확정):

- **권수·완독**: 보유 N권, 완독 M권, 완독률
- **장르/카테고리 비중**: (출처 = 알라딘 카테고리? — §7) 상위 장르 분포
- **저자 편향**: 최다독 저자, 저자 다양성
- **시간 분포**: 책별 누적 시간, 평균 세션 길이(정독 ↔ 다독), 총 독서 시간
- **다양성 vs 집중**: 장르 편식도(잡식 ↔ 편식)
- **신/구**: 출간연도 분포(최신작 ↔ 고전) — 메타 있으면

> 콜드스타트(책 2~3권)면 신호 부족 → §6 처리.

## 4. LLM 호출

- **프롬프트 골격**: "다음은 한 독자의 책장 요약 사실이다. **주어진 사실만 근거로**, 책을 지어내지 말고, MBTI 설명문처럼 이 사람의 독서 성향을 한 문단으로 서술하라." + 독서 프로필(JSON/표) 주입.
- **그라운딩**: "주어진 사실만" 명시 → 환각(없는 책·없는 장르 발명) 억제.
- **모델/비용**: 소형 모델(Claude Haiku / gpt-4o-mini / Gemini Flash 급). 입력 압축 프로필 + 한 문단 출력 → **호출당 1원 미만**. Gemini 무료 티어로 검증도 가능.
- **일관성**: temperature 낮게 + **결과 저장**(매 새로고침마다 글이 바뀌면 안 됨 — 사람들이 캡처·공유).

---

## 5. 출력 — 2겹 (설명문 + 비교 핸들)

plan.md 다운스트림이 둘이라 출력도 둘로 받는다:

1. **설명문** — 사람이 읽는 MBTI식 문단. (①책 추천·읽는 경험·프로필 노출)
2. **+ 짧은 태그/점수** — 예 `잡식·완독러·정독형` 또는 축별 점수. **기계가 비교·매칭하는 용도**. (②"비슷한 성향 독자"·궁합)

> ①만 할 거면 설명문만으로 충분. **②까지 갈 거면 태그를 같이 뽑아둬야** 나중에 안 갈아엎는다. LLM이 설명문과 함께 구조화 태그를 한 번에 내도록(JSON) 설계 가능.

---

## 6. 저장·갱신 / 콜드스타트

- **저장**: 파생 결과(설명문+태그)를 캐시/테이블에 저장. 매번 LLM 호출 안 함.
- **갱신 시점**: 책장이 **의미있게 변할 때**(권수·완독·장르 변동 임계 초과) 또는 사용자 **"다시 분석"** 버튼. → 호출 빈도 = 비용 핵심 변수를 바닥으로.
- **콜드스타트**: 책 너무 적으면(임계 미만) 분석 보류 + "조금 더 읽으면 성향이 보여요" 안내.

---

## 7. 프라이버시 경계 (sns §3.5와 동일 원칙 — 1순위)

- **분석 입력**: 본인 책장 전체로 본인용 결과는 OK. 단 **타인에게 노출되는 결과는 PUBLIC 책 기반만** — 안 그러면 비공개 책이 성향으로 **간접 누출**.
- 한 번 새면 회수 불가. 노출 경계는 사후 패치 아니라 설계에서 못 박는다.

---

## 8. 열린 질문 (착수 전 확정)

- 장르 분류 **출처**(알라딘 카테고리? ISBN→장르 매핑?) · 책 동일성 키(ISBN 정규화).
- 출력 2겹에서 **태그 체계**(축·라벨 네이밍) — ② 할 때만 필요.
- 결과 **저장 모델**(전용 테이블 vs 캐시) → Flyway 신규 여부.
- LLM **공급자 선택**(Claude/OpenAI/Gemini) · 키 관리 · 호출 실패/지연 시 폴백(설명문 없이 사실만 표시?).
- "본인용 vs 공개용" 결과를 **따로 생성**할지(입력 책 범위가 달라짐).
- 재미/오락 **정확도 기대치 고지**(과신 금지 — "가볍게 즐기는 것").
