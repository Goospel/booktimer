### 계획 md의 TDD 절 약화 금지 — 재발 사례 (2026-06-10)

계획 md가 'view/CSS라 새 테스트 안 만듦'으로 RED → GREEN을 약화해, 이 핸드오프를 읽는 구현 세션이 TDD를 건너뛸 빌미를 준 사례. 순수 시각 변경처럼 단위테스트가 무의미한 부분만 그 이유와 함께 preview/수동 검증을 게이트로 명시하되, 그게 TDD 전체를 건너뛰는 핑계가 되지 않게 한다.

### PR·머지 담당 = 구현 세션 — 근거 (사용자 합의 2026-06-09)

PR/머지는 설계가 아니라 **기계적 마무리**(git·요약·sweep·문서 한 줄)라 저-effort 쪽 일이고, 방금 diff를 만든 세션이 PR body·changelog를 가장 정확·싸게 쓴다(설계 세션이 하면 구현 컨텍스트를 강한 모델에 재로딩 = 낭비). 문서 처리(changelog 새 행·plan.md 본문 점검)는 계획 md가 이미 선결정해 둬 구현 세션은 판단 없이 실행만 한다. ~~**예외**: 회귀 리스크 큰 작업만 머지 전 독립 리뷰 패스(설계 세션이든 `/code-review`든)를 opt-in — 평상시엔 드리프트 규칙+TDD 게이트가 적합성을 커버하므로 불필요.~~ (← 2026-08-22 재개정으로 폐지 — 바로 아래 절.)

**세션 분리의 트레이드오프**: 통제력(세션별 모델·effort 수동 배정) ↔ 마찰(md 작성·세션 왕복). 큰 작업에서만 통제력이 마찰을 이긴다. 한 세션 안 subagent(계획 서브에이전트 → 메인이 구현)도 대안이나, 세션 단위 모델 통제를 원하면 2세션이 더 확실하다.

### reviewer opt-in → 밝은선 4종 필수 — 재개정 경위 (사용자 선택 2026-08-22)

위 「회귀 리스크 큰 작업만 opt-in」은 재개정으로 폐지됐다. 근거 둘:

- **실측 붕괴**: 벨트 로그(`~/.claude/logs/subagent-model.jsonl`) 기준 reviewer 호출이 08-13 분업 개정 전 94건(호출의 27%) → 개정 후 2건(3%)으로 무너졌다. "회귀 리스크 큰"의 판정 기준이 없어 기본값이 「리뷰 없음」으로 굳은 것 — designer 사문화(0.8%)와 동일한 실패 모드다. **모호 기준은 0으로 수렴한다.**
- **opt-in 전제의 반박**: 근거였던 「평상시엔 드리프트 규칙+TDD 게이트가 커버」는 그 뒤의 실측이 반박했다. T-183은 단위 736건 전부 GREEN인 채 새 구멍 2건을 통과시켰고(TDD가 원리상 못 잡는 클래스), 알라딘 `&amp;` 3회차는 **53줄 diff**가 제휴 수수료 전체를 7주 무추적으로 만들었다(작은 diff ≠ 작은 리스크). 위 「테스트 깊이」 절의 독립성 함정("구현·테스트를 둘 다 Claude가 짜면 같은 가정을 공유 — 독립 검증은 결국 리뷰")도 같은 방향을 가리킨다.

기준 4종(마이그레이션 / 보안·인증 / 수익 경로 / 코드 ±150줄+)은 최근 40 PR 실측으로 설계했다 — 코드 PR 23건 중 14건(61%) 발동, 민감 경로 3종은 드물지만(1·0·2건) 「작아도 참사」인 자리라 줄 수와 무관하게 잡는다. 검토·기각한 대안: 코드 PR 전부(100% — reviewer가 opus·xhigh라 비용 과다) / ±300줄 기준(~45% — 150~300줄대 중형 변경 4건이 사각) / 문구만 교정(비용 0이나 모호 기준 재발 위험 — designer 전례상 기각).

### 세션 메타 effort — `unknown` 폴백 금지 → 항목 자체 폐지 (2026-06-27 → 2026-08-13)

**처음(2026-06-27)엔 강화**했다: 새 세션이 시작 시 effort 미고지면 묻지 않고 `unknown`을 박아 추적값이 비던 사례가 있어, `unknown` 폴백을 "다시 묻기"로 대체했다(`unknown`은 사용자가 명시적으로 "모름/미정"이라 답한 경우에만).

**2026-08-13 폐지 (커밋 trailer 한정)**: 그 강화가 곧 마찰의 정체였다 — effort는 세션 컨텍스트에 안 들어오므로 "다시 묻기"란 결국 **매 커밋 사용자를 붙잡는다**는 뜻이었고, 실제로 그렇게 작동했다. 더 근본적으로는 **서브에이전트 분업이 기본이 되며 "한 커밋 = 한 effort" 전제가 깨졌다** — 커밋 하나에 designer(fable·high)·implementer(opus·high)·operator(opus·low)가 섞이는데 코디네이터 세션 값을 적으면 실제 산출자를 가리키지 않아, 빈 값보다 나쁜 **틀린 값**이 된다. 그래서 `Session-Effort`를 폐지하고 `Session-Model`만 남겼다.

- **계획 md의 effort는 유지** — 그건 서브에이전트가 쓰고, 서브에이전트는 자기 effort를 정의 파일 frontmatter에서 알아 마찰이 없다(실측: `docs/2026-08-11-reward-ad-iaa-design.md`의 `effort=high(에이전트 정의 frontmatter)`).
- **대체물이 이미 있었다** — 서브에이전트별 모델은 훅 `force-subagent-model.ps1`이 벨트 로그에 자동 기록한다. 수동 trailer는 그 열등 사본이었다. trailer에 남는 유일한 고유 가치는 "로컬 로그와 달리 `main`에 영구 보존"인데, 그건 모델만으로도 확보된다.
- **교훈**: 사람이 매번 값을 대야 하는 추적 필드는, 그 값이 자동으로 안 채워지는 순간 **규칙을 강화할 게 아니라 필드의 존재 이유를 다시 물어야** 한다. 여기선 강화(2026-06-27) 후 1.5개월 만에 전제 자체가 무너졌다.

### docker-cleanup 상세

스크립트는 `com.docker.compose.project.working_dir` 라벨로 **BookTimer 소속(메인+모든 워크트리)만** 지우고 다른 프로젝트는 보호한다. 특정 워크트리만 내릴 땐 그 폴더에서 `docker compose down`. `--all`은 Up까지 죽이니 다른 세션이 그 워크트리에서 `bootRun` 중이면 기본(Exited만)을 쓴다. `SessionEnd` 훅 `cleanup-docker-on-session-end.ps1`(2026-06-27, gap#3 자동배선)이 기본 모드를 세션 종료마다 자동 호출한다 — fail-open(docker 없거나 실패해도 종료를 막지 않음), 테스트 `.claude/hooks/tests/test-cleanup-docker-on-session-end.sh`.

## TDD

### 테스트 깊이 — "작성 시간이 싸져도 안 사라지는 비용" 전문 (사용자 합의 2026-06-06)

Claude가 테스트를 빨리 짜므로 "사람 작성 시간"이라는 전통적 상한은 풀렸다. 하지만 다음 비용은 빨리 짜도 안 사라진다:

- **유지보수·브리틀니스** — 구현 디테일(정확한 문자열·내부 구조)까지 검증하면 리팩터링마다 가짜로 깨진다. 깨진 테스트가 진짜인지 가짜인지 판단하는 비용은 사용자도 같이 낸다.
- **실행 시간** — 커밋 게이트가 매 `.java` 커밋마다 `./gradlew test`를 돌린다. MockMvc·@SpringBootTest는 무거워 수가 불면 개발 루프 전체가 느려진다 → 로직은 빠른 단위 테스트, 통합 테스트는 배선 확인용으로.
- **신호 희석** — 테스트 묶음은 "이게 뭘 하기로 한 코드인가"의 명세로 읽힌다. 트리비얼 다수에 진짜 도메인 규칙이 묻히면 읽는 사람에게 독이다.
- **독립성 함정** — 구현과 테스트를 둘 다 Claude가 짜면 같은 잘못된 가정을 공유한다(상관관계). "내 테스트 N배 = 안전 N배"가 아니다 → 독립 검증은 결국 사용자가 명세한 의도와 리뷰다.

그래서 늘어난 예산은 변형 테스트 양산이 아니라 옳은 곳에 깊이로 쓴다.

## 프론트 검증

### 왜 실 브라우저인가 — 전문 (사용자 합의 2026-06-15)

`defer`/`async`/`type=module`은 스크립트의 **실행 시점**을 바꿔, 같은 소스라도 로드 순서가 달라진다. 헤드리스 재현이 라이브러리를 동기 로드하면 순서가 뒤바뀌어 **버그가 사라진 가짜 green**이 나온다 — 단위테스트·POC는 통과하는데 실페이지만 깨진다. 실제로 #356~#358·#364(정원 Phaser 위젯)가 이 사각으로 반복해서 새어, Chrome 확장으로 실페이지 콘솔을 직접 읽고서야 잡혔다. 개념: learning-notes N-083(defer × `class extends` TDZ)·N-082(reactive Proxy), 함정 T-053·T-054.

### E2E(Playwright)를 커밋 훅에 넣지 않는 이유 — 전문 (2026-06-26 결정)

E2E는 실서버(`bootRun`)·Docker·브라우저가 전제라 매 커밋마다 돌리면 수 초 게이트가 수 분으로 불고, 멀티세션 8080 경합·플래키로 `SKIP_TESTS` 우회를 습관화시켜 게이트를 무력화한다. per-commit이 아니라 **머지 전** 레이어가 맞다. 실행법·결과 육안 확인은 learning-notes N-127, 도입 배경·판단은 N-084.

## CSRF 폼 세션 선확정

### 왜 — 전문 (T-033·T-049, 4회+ 재발)

Thymeleaf가 폼의 CSRF 숨김필드를 그릴 때 세션을 **lazy 생성**하는데, 페이지가 크면 그 시점엔 응답 버퍼(기본 ~8KB)가 이미 커밋된 뒤다 — 커밋 후 `getSession(true)`는 `IllegalStateException("Cannot create a session after the response has been committed")`로 터져 그 페이지만 500이 난다. 익명 폼(로그인·가입·비번재설정·이메일검증·구독해지)과 폼이 여럿인 큰 페이지(설정 등)가 특히 위험. 개념: learning-notes N-077.

### 훅으로 강제하지 않는 이유

"th:action 폼 템플릿을 렌더하는 GET 핸들러인데 선확정이 없다"를 정적 감지하려면 컨트롤러↔템플릿 역매핑·POST 재렌더 분기 때문에 오탐(FP)이 30~50%라 게이트가 무력화된다 — 그래서 prose 규칙 + 코드 리뷰가 담당한다(하드픽스 부적합 사례).
