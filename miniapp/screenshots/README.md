# 미니앱 스토어 스크린샷

앱인토스 콘솔에 올리는 **스토어/심사용 스크린샷** 보관소. 미니앱 코드와 무관한 콘솔 자산이라
번들에 실리지 않고, 배포(`miniapp/deploy.sh`)와도 관계없다. 여기 두는 이유는 심사 때마다
다시 찍는 수고를 없애고 "지금 올라가 있는 그림"이 무엇인지 레포에서 추적하기 위해서다.

→ ⚠️ 촬영기에 판단 한 줄이 붙었다: 목 픽스처가 달력 표식을 **최근 4일**에 놓아, 달 초에 찍으면 그
표식들이 지난달에 있어 이번 달이 백지로 나온다(09-01 실측). 표식이 0개면 지난달로 한 칸 물러선다.
→ 06은 목 픽스처의 공부 목표·오늘 시간이 0이라 게이지 대신 `00:00`과 「목표 정하기」로 선다. 이 값을
채우려면 앱 소스(`dev-mock.ts`)를 고쳐야 해 여기선 그대로 뒀다 — 첫날의 정직한 상태이기도 하다.

## 재촬영 — `shoot.mjs` 한 방

```
npm --prefix miniapp run dev:mock      # 목 서버(포트 5300)를 먼저 띄운다
node miniapp/screenshots/shoot.mjs     # 9장을 규격대로 덮어쓴다
```

포트의 단일 출처는 체크인된 `miniapp/vite.config.ts`의 `server.port`(**5300**)다. 다른 포트로 띄웠으면
(다른 세션이 5300을 쓰는 중이면) 주소를 넘긴다:
`MINIAPP_MOCK_URL=http://localhost:5301 node miniapp/screenshots/shoot.mjs`

세로 8장 + 가로 배너를 한 번에 만든다. 의존성은 `frontend/node_modules`의 playwright·sharp를 빌려
쓴다(스크린샷은 번들과 무관한 콘솔 자산이라 미니앱에 촬영용 의존성을 새로 달지 않는다).

⚠️ **이 스크립트가 저장소에 있는 이유**: 2026-08-14 촬영 땐 스크래치패드에 뒀다가 세션과 함께
날려서, 2026-08-16 재촬영 때 처음부터 다시 짰다. 화면이 바뀔 때마다 반복될 비용이라 여기 박았다.

**2026-08-29 재촬영 — 식물 성장 카드 폐기 후, 다만 구도는 그대로 뒀다**: 기록 화면 상단의 성장 카드가
담백한 스탯 줄(연속·읽은 날·총 시간)로 바뀌어 재촬영했다. 결과는 **`04-history`(+ 그걸 얹은
`10-landscape`)만 변경, 나머지 4장은 바이트째 동일** — 그 넷이 안 바뀌었다는 증거다.
→ ⚠️ **그런데 그 diff는 UI 변경분이 아니라 잔디·날짜의 오늘 기준 이동이다.** 이 컷은 「읽은 날짜」를
기준선으로 잡아 **스탯 줄보다 아래에서 시작**하므로, 바뀐 자리가 애초에 화면 밖이다.
→ **위에서부터 찍는 구도로 바꿀지 재봤다(실측 375×618): 스탯 줄 78 · 잔디 제목 148 · 표지 더미 행 465 ·
탭바 550.** 즉 카드가 사라져 **표지 더미가 이제 위에서 찍어도 보인다** — 아래 2026-08-20 항목이 든
「0에서 찍으면 더미가 안 보인다」는 근거는 소멸했다. 그럼에도 **구도는 유지**한다: 위에서 찍으면 펼친
책 줄이 **한 줄로 줄고 그마저 탭바에 잘리며** 표지 조각이 탭바 아래 걸쳐 남는다(「잘린 문장은 심사용
그림이 아니다」와 같은 이유). 이 컷이 파는 것은 **책별로 얼마나 읽었나**이므로 펼침이 온전한 쪽이 낫다.

## ⚠️ 지금 들어 있는 파일은 목 모드 캡처다 (2026-08-20 재촬영)

실계정 화면과 권수·시간·닉네임이 다르다. UI 구성·레이아웃은 실제와 같다.

펼침**이 없었다(#880 — 하루에 여러 권 읽은 날을 겹쳐 쌓고 눌러 펼치면 책별 시간). ② `03-library`에
**「2시간 읽음」·「공개」 칩**이 없었다(#879 — 전에는 저자 아래 회색 글자였다). ③ `02-feed`에 소식
**표지와 「다 읽음」 배지**, 그리고 **「함께 읽는 사람」 탭**이 없었다(#870·#878). `01-home`·`05-goal`은

## 촬영 조건

- **원칙은 실기기(토스 앱) 캡처다.** 브라우저 목 모드로는 실데이터가 안 나오고, 실계정
  토큰은 토스 SDK의 `authorizationCode`로만 발급돼(`TossAuthApiController`) 브라우저·curl로
  만들 수 없다. 목 모드 캡처는 UI가 실제와 같다는 전제 위에서 쓰는 대용품이다.
- 라이트 모드 · 상단 상태바의 알림 배지나 개인 정보는 정리하고 찍는다.
- 화면이 바뀌면(홈 구성·탭바 등) 해당 파일만 다시 찍어 교체한다 — 옛 그림이 콘솔에 남으면
  심사에서 실제 앱과 다르다는 지적을 받는다.

## 규격

**콘솔 실측(2026-08-14 업로드 화면):**

| 형태 | 크기 | 최소 장수 |
|---|---|---|
| 세로형 | **636 × 1048** | 3장 |
| 가로형 | **1504 × 741** | 1장 |

크기가 안 맞으면 **업로드 자체가 거부된다**(비율만 맞추는 게 아니라 정확한 픽셀이어야 한다).

세로는 **375×618 뷰포트 @2(=750×1236)로 찍어 636×1048로 축소**한다 — 375/618 = 0.6068 이
규격 비율 0.6069와 사실상 같아 축소해도 찌그러지지 않는다. 636 폭으로 직접 렌더하면 CSS 폭이
폰이 아니게 되어 레이아웃이 달라진다(그러면 실제 앱과 다른 그림이 된다).

가로는 앱에 가로 화면이 없으므로 세로 컷을 얹은 배너를 만든다. 폰을 캔버스 아래로 흘려 보내면
크롭된 변이 "잘렸다"가 아니라 "아래에서 올라온다"로 읽힌다.

⚠️ **배너의 종이색·서체는 앱을 따라간다** — 배너는 앱 컷을 얹은 합성물이라 여기만 옛 값이면
폰 안팎이 다른 톤·다른 서체로 갈린다. 실제로 「거친 종이 위에 연필로」 테마 전환 때 배너가 옛
종이색(`#F3EEE4`)과 고딕(Gowun Dodum)에 남아 손글씨 폰 3장과 따로 놀았다(2026-08-19에 교정).
**앱의 색 토큰이나 본문 서체를 바꾸면 `shoot.mjs`의 배너 CSS도 같이 본다.**

(앱 로고는 600×600 — `miniapp/icon/` 참고.)
