# 미니앱 스토어 스크린샷

앱인토스 콘솔에 올리는 **스토어/심사용 스크린샷** 보관소. 미니앱 코드와 무관한 콘솔 자산이라
번들에 실리지 않고, 배포(`miniapp/deploy.sh`)와도 관계없다. 여기 두는 이유는 심사 때마다
다시 찍는 수고를 없애고 "지금 올라가 있는 그림"이 무엇인지 레포에서 추적하기 위해서다.

## 파일명

`NN-화면.png` — 콘솔에 올리는 순서가 곧 번호다.

| 파일 | 화면 | 규격 |
|---|---|---|
| `01-home.png` | 홈 — 타이머 카드 + 표지 캐러셀 | 세로 |
| `02-feed.png` | 홈(아래) — 「소식」·「책 뉴스」 피드 박스 | 세로 |
| `03-library.png` | 서재 — 상태 탭 + 표지 캐러셀 | 세로 |
| `04-history.png` | 기록 — 통계 + 잔디 + 날짜별 기록 | 세로 |
| `05-goal.png` | 목표 — 시/분 휠 피커 | 세로 |
| `10-landscape.png` | 가로형 배너(앱 화면이 아니라 **세로 컷 3장을 얹은 합성물**) | 가로 |

세로 규격 높이(1048)로는 홈이 한 화면에 안 들어와 **홈을 두 컷**으로 나눴다 — 위(타이머·캐러셀)와
아래(피드 박스). 피드는 폴드 아래라 스크롤해 찍는다.

## ⚠️ 지금 들어 있는 파일은 목 모드 캡처다 (2026-08-14)

세로 5장은 **브라우저 목 모드**(`npm --prefix miniapp run dev:mock`)를 Playwright로 찍은 것이다
— 사용자가 "실사와 좀 달라도 된다"고 판단해 그렇게 정했다. 데이터는 `src/dev-mock.ts` 픽스처라
실계정 화면과 권수·시간·닉네임이 다르다. UI 구성·레이아웃은 실제와 같다.

재촬영 스크립트는 세션 스크래치패드라 휘발됐다(재작성 쉬움 — Playwright + `frontend`의 `sharp`로
뷰포트 375×618·`deviceScaleFactor: 2`·`colorScheme: 'light'`로 찍어 636×1048로 축소, 하단 탭바
`button[role="tab"][title="…"]`를 눌러 이동, 촬영 직전 `document.activeElement.blur()`).

## 촬영 조건

- **원칙은 실기기(토스 앱) 캡처다.** 브라우저 목 모드로는 실데이터가 안 나오고, 실계정
  토큰은 토스 SDK의 `authorizationCode`로만 발급돼(`TossAuthApiController`) 브라우저·curl로
  만들 수 없다. 목 모드 캡처는 UI가 실제와 같다는 전제 위에서 쓰는 대용품이다.
- 라이트 모드 · 상단 상태바의 알림 배지나 개인 정보는 정리하고 찍는다.
- 화면이 바뀌면(홈 구성·탭바 등) 해당 파일만 다시 찍어 교체한다 — 옛 그림이 콘솔에 남으면
  심사에서 실제 앱과 다르다는 지적을 받는다.

## 규격

**콘솔 실측(2026-08-14 업로드 화면):**

| 형태 | 크기 | 최소 장수 |
|---|---|---|
| 세로형 | **636 × 1048** | 3장 |
| 가로형 | **1504 × 741** | 1장 |

크기가 안 맞으면 **업로드 자체가 거부된다**(비율만 맞추는 게 아니라 정확한 픽셀이어야 한다).

세로는 **375×618 뷰포트 @2(=750×1236)로 찍어 636×1048로 축소**한다 — 375/618 = 0.6068 이
규격 비율 0.6069와 사실상 같아 축소해도 찌그러지지 않는다. 636 폭으로 직접 렌더하면 CSS 폭이
폰이 아니게 되어 레이아웃이 달라진다(그러면 실제 앱과 다른 그림이 된다).

가로는 앱에 가로 화면이 없으므로 세로 컷을 얹은 배너를 만든다. 폰을 캔버스 아래로 흘려 보내면
크롭된 변이 "잘렸다"가 아니라 "아래에서 올라온다"로 읽힌다.

(앱 로고는 600×600 — `miniapp/icon/` 참고.)
