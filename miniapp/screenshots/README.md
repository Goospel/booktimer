# 미니앱 스토어 스크린샷

앱인토스 콘솔에 올리는 **스토어/심사용 스크린샷** 보관소. 미니앱 코드와 무관한 콘솔 자산이라
번들에 실리지 않고, 배포(`miniapp/deploy.sh`)와도 관계없다. 여기 두는 이유는 심사 때마다
다시 찍는 수고를 없애고 "지금 올라가 있는 그림"이 무엇인지 레포에서 추적하기 위해서다.

## 파일명

`NN-화면.png` — 콘솔에 올리는 순서가 곧 번호다.

| 파일 | 화면 | 규격 |
|---|---|---|
| `01-home.png` | 홈 — 인사말·아바타 헤더 + 타이머 카드 + 표지 캐러셀 | 세로 |
| `02-feed.png` | 홈(아래) — 「소식」·「책 뉴스」 피드 박스 | 세로 |
| `03-library.png` | 서재 — 상태 탭 + 표지 캐러셀 + 인라인 여백 박스 | 세로 |
| `04-history.png` | 기록 — 통계 + 잔디 + 날짜별 기록 | 세로 |
| `05-goal.png` | 목표 — 시/분 휠 피커 | 세로 |
| `10-landscape.png` | 가로형 배너(앱 화면이 아니라 **세로 컷 3장을 얹은 합성물**) | 가로 |

(`shoot.mjs`는 그림이 아니라 **재촬영기**다 — 아래 「재촬영」 참고.)

세로 규격 높이(1048)로는 홈이 한 화면에 안 들어와 **홈을 두 컷**으로 나눴다 — 위(타이머·캐러셀)와
아래(피드 박스). 피드는 폴드 아래라 스크롤해 찍는다.

## 재촬영 — `shoot.mjs` 한 방

```
npm --prefix miniapp run dev:mock      # 목 서버(포트 5174)를 먼저 띄운다
node miniapp/screenshots/shoot.mjs     # 6장을 규격대로 덮어쓴다
```

세로 5장 + 가로 배너를 한 번에 만든다. 의존성은 `frontend/node_modules`의 playwright·sharp를 빌려
쓴다(스크린샷은 번들과 무관한 콘솔 자산이라 미니앱에 촬영용 의존성을 새로 달지 않는다).

⚠️ **이 스크립트가 저장소에 있는 이유**: 2026-08-14 촬영 땐 스크래치패드에 뒀다가 세션과 함께
날려서, 2026-08-16 재촬영 때 처음부터 다시 짰다. 화면이 바뀔 때마다 반복될 비용이라 여기 박았다.

## ⚠️ 지금 들어 있는 파일은 목 모드 캡처다 (2026-08-17 재촬영)

세로 5장은 **브라우저 목 모드**(`npm --prefix miniapp run dev:mock`)를 Playwright로 찍은 것이다
— 사용자가 "실사와 좀 달라도 된다"고 판단해 그렇게 정했다. 데이터는 `src/dev-mock.ts` 픽스처라
실계정 화면과 권수·시간·닉네임이 다르다. UI 구성·레이아웃은 실제와 같다.

**2026-08-17 재촬영 사유 — 출시 직전 점검에서 5장이 낡아 있었다**: ① 하단 탭바가 **4칸**으로 찍혀
있었는데 지금은 **5칸 + 가운데 측정 원**이다(#832). 탭바는 세로 4장 전부에 나오므로 예외가 없었다.
② `01-home`에 지금은 없는 **홈 하단 「측정 시작」 풀폭 버튼**이 박혀 있었다(같은 PR로 탭바로 올라갔다).
③ `01-home` 최상단이 옛 **「프로필·설정」 알약**이었는데 지금은 **인사말 + 아바타 헤더**다(#838).
`05-goal`은 그 화면이 안 바뀌어 **바이트째 그대로**였다(재촬영해도 동일 — 그게 안 바뀌었다는 증거다).
→ ⚠️ 이번엔 **재촬영기 자체도 두 군데 고쳐야 돌아갔다**: 탭 선택 셀렉터가 `role="tab"`이었는데 탭바가
ARIA tabs 패턴을 버려(`aria-current="page"`) 죽었고(#832), 첫 사용 안내(코치마크)가 생겨 갓 띄운
브라우저에서 딤이 깔린 채 **스스로 탭을 옮기며** 촬영을 어긋내므로 `addInitScript`로 「이미 다 본
사용자」를 심는다(#833~#837). 화면을 바꾸는 PR은 이 폴더뿐 아니라 `shoot.mjs`도 같이 본다.

**2026-08-16 재촬영 사유 — 6장 전부가 낡아 있었다**: ① 하단 탭바가 「소셜」(사람 아이콘)로 찍혀
있었는데 지금은 **「책방」(가게 아이콘)**이다(#812~#813). 탭바는 모든 컷에 나오므로 한 장도 예외가
없었다. ② `02-feed`의 소식에 **여백 줄**이 빠져 있었다(#816). ③ `01-home`·가로 배너에 지금은 없는
**「목표 30분 ›」 칩**이 박혀 있었다(2026-08-14 홈 개편으로 「남은시간 ⓘ」 상자로 흡수됨).
→ 화면을 바꾼 PR에서 이 폴더를 함께 sweep 하지 않으면 이렇게 조용히 밀린다. **UI를 바꿨으면
`shoot.mjs`를 한 번 돌린다**가 가장 싼 방어다.

## 촬영 조건

- **원칙은 실기기(토스 앱) 캡처다.** 브라우저 목 모드로는 실데이터가 안 나오고, 실계정
  토큰은 토스 SDK의 `authorizationCode`로만 발급돼(`TossAuthApiController`) 브라우저·curl로
  만들 수 없다. 목 모드 캡처는 UI가 실제와 같다는 전제 위에서 쓰는 대용품이다.
- 라이트 모드 · 상단 상태바의 알림 배지나 개인 정보는 정리하고 찍는다.
- 화면이 바뀌면(홈 구성·탭바 등) 해당 파일만 다시 찍어 교체한다 — 옛 그림이 콘솔에 남으면
  심사에서 실제 앱과 다르다는 지적을 받는다.

## 규격

**콘솔 실측(2026-08-14 업로드 화면):**

| 형태 | 크기 | 최소 장수 |
|---|---|---|
| 세로형 | **636 × 1048** | 3장 |
| 가로형 | **1504 × 741** | 1장 |

크기가 안 맞으면 **업로드 자체가 거부된다**(비율만 맞추는 게 아니라 정확한 픽셀이어야 한다).

세로는 **375×618 뷰포트 @2(=750×1236)로 찍어 636×1048로 축소**한다 — 375/618 = 0.6068 이
규격 비율 0.6069와 사실상 같아 축소해도 찌그러지지 않는다. 636 폭으로 직접 렌더하면 CSS 폭이
폰이 아니게 되어 레이아웃이 달라진다(그러면 실제 앱과 다른 그림이 된다).

가로는 앱에 가로 화면이 없으므로 세로 컷을 얹은 배너를 만든다. 폰을 캔버스 아래로 흘려 보내면
크롭된 변이 "잘렸다"가 아니라 "아래에서 올라온다"로 읽힌다.

(앱 로고는 600×600 — `miniapp/icon/` 참고.)
